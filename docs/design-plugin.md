# 插件化本体架构设计稿（design-plugin）v0.1

> **卷首语**：整个架构源自 Pi/DSH——世界=对抗性 agent 宿主，玩家=agent/插件，宪法=运行时契约（土豆顿悟，2026-10-18）。开源叙事：不是开源一个游戏，是开源一个对抗性 agent 世界引擎。
> **状态**：v0.1 设计任务书稿（2026-10-24），前置 D-005 刀0 已落地（决斗会话+游魂读写原语在库）。**待土豆终审**。

## 一、问题（现状缺陷与动机）

现状本体=单体 WASM 模块：一名玩家一个 .wat，行为（战斗/防御/求生）全写死在一块代码一块内存里。三个死结：

1. **"改引擎"死结**：想升级某项行为=重写整个模块（旧内存整体报废）；攻方想操纵守方行为=只能改数据（改魂），不能换行为——因为"行为"没有独立可替换的单元。决斗制已把"换血"判退役，但退役后攻方战果谱里的"换装"仍无处落地：**没有插件，就没有可换的装**（dev-plan：夺舍换插件要等插件存在）。
2. **协作粒度死结**：想把"自动打怪"外包给朋友写的模块？现状只能整脑替换（copy 整个 .wat），没有"只借一个器官"的通道。零代码玩家想获得现成行为，同样无路（模板生态缺机制层载体）。
3. **防御纵深死结**：design-duel §5 已定案"守方赌注=本体+插件当拍余额（防御深度=器官们能烧多少）"——插件不存在，这条已立宪法就没有工程落点。

## 二、宪法原则（引用为主，本刀新裁决显式标出）

**已有定案直接引用（勿再议）：**

- 居民四形态（design-duel §6）：本体=连接器（永不可改，BIOS）+插件们；**插件=沙箱造的无身器官，随本体死**；造物=儿子独立生死；判据一句话：有沙箱=居民。
- 攻防目标清单封版（design-duel §6）：连接器不可攻（压舱石）；**插件可换装/改魂/拔除（攻防主战场）**；魂可偷/污/改；身体走物理；造物走契约产权。
- 记账铁律 #046：谁的代码在跑烧谁的步数，账户跟人不跟房子。延伸到插件：**插件沙箱的一切 API 调用，身份=本体实体 id**（器官出手=本人出手，产权/攻击溯源/法律后果全归本体；插件无独立身份，无身=无 id）。
- 通道公理 #038：世界只修路不跑车。插件间要协作，路是世界修的吗——见 §五裁决。
- 引擎不可改（决斗宪法 3）：连接器的"永不可改"是攻防语义（攻方不可改），玩家自己重写自己 .wat=换脑子，世界照旧不管（#024 重进场语义不变）。

**本刀新裁决（⚠ 待土豆拍板项，逐条给推荐）：**

- **裁决 P1（驾驶通道不插件化）**：dev-plan 原文四器官清单"战斗/防御/求生/听鼠标"修正为三器官+自由长——**听鼠标永不成为插件**。理由：驾驶通道在 host 侧（意图路由，#022/#027），决策在玩家大脑，这正是"驾驶者免疫夺舍"（决斗宪法 5）的实现根基；若听鼠标入插件，游魂改魂即可劫持操控，违宪。驾驶的"感知"同理走前端快照（所见即所判，屏幕内无欺骗），不经过本体沙箱。
- **裁决 P2（连接器=现有 .wat 沙箱的正名，非新建层）**：连接器不是新增组件——**现在玩家进场的那个 .wat 沙箱就叫连接器**。插件化=允许（不强制）把行为从连接器拆出去挂插件；单体玩家=连接器裸奔（无插件，全部行为在连接器），**永久合法形态**（同决斗制"裸奔特例"哲学，存量玩家零破坏）。
- **裁决 P3（压舱石=结构性无地址，非只读区）**：守方全内存皆战场（决斗宪法2）**原样适用于连接器内存**——裸奔实体的魂就住在连接器里，对其划只读区=改魂战果对裸奔者失效，违已立宪法。"永不可改"的工程实现：**身份链与插件表本来就不在沙箱内存里**（现状即如此：#043 身份链与产权住 host 侧实体记录，code_hash 住 storage 表）——压舱石无地址可写，不是被保护而是不存在于战场。攻防效果：游魂看得见插件表吗？插件表是 host 侧数据，**读它走将来的 probe 应答**（守方可谎报器官清单——信息战归应答层，物理层永远诚实）；游魂写得着的只有沙箱内存（连接器+插件），那正是宪法允许的全部。
- **裁决 P4（插件生死=器官语义，世界不当保姆）**：插件死（崩溃/被拔）≠本体死——器官衰竭，本体活着失去该功能。**世界永不自动重启插件**（重启=免费满血，攻击白打）；检测与重挂=连接器代码自己的事（自我修复是玩法，归玩家写）。插件死亡不触发本体 on_death。
- **裁决 P5（fuel 各自一箱）**：每插件每拍独立一箱 fuel（同现有沙箱语义：私有制不借贷——一个插件死循环烧死自己不烧兄弟）。堆插件=堆防御纵深是**特性不是漏洞**（design-duel §5 已定案"防御深度=器官们能烧多少"；废插件白占槽不产生防御力，防御力=代码质量×数量，真实成本=玩家写代码+槽位）。
- **裁决 P6（并行意图仲裁=装载序先到优先）**：多插件同拍各排移动意图时，**按装载序取第一个生效**（装载序=确定序，确定性红线 #044；装载序即优先级序，玩家 mount 的顺序自己负责）。想合力=写进同一个插件（世界不做矢量合成——那是把意图改用力语义，超纲）。攻击/造物不冲突（本就排队收集多笔），但**每实体每拍限流配额全体共享**（插件再多，attack_at 每拍 1 刀、spawn 每拍 1 个照旧——防插件刷攻击刷造物）。操控意图最后覆盖一切（驾驶>器官，与现状"操控刀优先"一致）。
- **裁决 P7（插件代码来源自由，世界不问出处）**：mount 传入的是连接器内存里的字节——字节怎么来的（编译时打包进 data 段/从造物内存拷来/bridge 从外部下载）世界一概不管，同 birth_blob"世界不解释内容"哲学。外脑供器官（bridge 下载一个战术插件装上）=外接算力桥的自然涌现，零新立法。

## 三、本体解剖图（三层）

```
玩家大脑（鼠标/键盘）                    ← 永不在沙箱内（裁决 P1）
   │ 意图流（host 侧路由，#022/#027）
   ▼
┌─ 本体实体（一具身体，世界结算）─────────────────┐
│  连接器沙箱（=现有 .wat；身份链+插件表+life 自决） │ ← 只读战场（裁决 P3）
│    ├ 插件槽 0：战斗器官沙箱（无身）              │ ← 读写战场
│    ├ 插件槽 1：防御器官沙箱（无身）              │ ← 读写战场
│    └ …（槽上限=常数，见 §五）                    │
└──────────────────────────────────────────────┘
   ▼ 意图汇聚点（host 侧）：插件意图按装载序 + 操控意图最后覆盖
世界（结算引擎：物理/碰撞/攻击/掠夺…照常）
```

- 连接器职责（现状全部保留）：life() 生死自决、on_tick 主逻辑（裸奔形态时）、身份链持有（#043 两级身份链的角色端）、**新增：插件表管理（mount/unmount）**。
- 插件职责：纯行为器官。可导出与连接器同款契约面（on_tick/on_attack/on_probe/on_contact…——防御插件吃 on_attack、感知插件吃 on_contact，天然分工）。
- **插件 import 面=与本体同款全套 20 个**（不裁剪）。理由：一个沙箱一份权利（居民权利对等，判据=有沙箱）；"插件该少些权限"是世界替玩家管安全的家长制，玩法上的分工归玩家自己写。行为记账全归本体 id（#046 延伸，见 §二）。
- 插件无坐标无 glyph 无 radius：**前端零渲染**（快照不加插件字段——插件的存在感走 probe 应答博弈，守方可谎报装了什么；屏幕内无欺骗不破）。

## 四、装载契约

- **新 import 两个（第 21/22 号）**：
  - `mount(code_ptr: i32, code_len: i32) -> i32`：从连接器内存取 WAT/WASM 字节，编译校验（同进场编译管线），装入下一个空槽。返回槽号（≥0 成功）；-1=字节无效/编译失败，-2=槽满，-3=每拍限流（每实体每拍最多 mount 1 次，与 spawn 限流同款）。
  - `unmount(slot: i32) -> i32`：拔除指定槽（0 成功；-1=槽号无效）。被拔插件内存当场销毁（无残影——无身无占位）。
- **装载时机**：进场后任意拍（on_tick 里调用即装即用，下一拍起插件开始跑）。进场"初始插件包"不需要新目录契约——连接器第一拍自己 mount（data 段自带字节）即等价。
- **槽上限**：每本体 MAX_PLUGINS（建议初值 4，常数入 game-menu 1.7 总账；升限信号=玩家实测喊不够）。资源护栏家族（同实体上限 64），非平衡补丁。
- **插件无 entity_id**：挂表=实体记录上的 `Vec<PluginSandbox>`，一切外部寻址以 (本体 id, 槽号) 进行。
- **持久化**：插件表（代码 hash+装载序）随实体快照序列化，插件**内存不持久化**（与现有沙箱内存同款语义：世界重启/重进场即清，器官记忆随会话）。

## 五、生死与账本

- **四条死路的插件版**：本体四条死路不变（life 自断/崩溃/燃料尽/点数尽——连接器停=本体死，插件随本体死）。插件自己的死路两条：崩溃（编译过的代码运行时炸=该插件死，不连坐本体）、被拔（unmount/将来被游魂换装）。插件 fuel 尽=当拍没力气，下拍重发（同本体"穷一拍穷不了一生"，fuel 是保险丝非生命值）。
- **fuel 账本（裁决 P5）**：连接器一箱+每插件一箱，各自独立，每拍重发。攻防会话守方总兵力=Σ全部箱子的当拍余额（design-duel §5 落地）。
- **意图仲裁总表（裁决 P6）**：

| 意图类型 | 规则 |
|---|---|
| 移动 | 每实体每拍取 1 个：插件按装载序先到优先，操控意图最后覆盖 |
| 攻击 | 每实体每拍 1 刀（全体共享配额），多插件抢本拍=装载序第一个生效 |
| 造物/销毁 | 每实体每拍 1 个（共享），产权校验按本体 id |
| 感知（scan/probe） | 各跑各的互不占额（读操作不冲突） |
| mount/unmount | 每实体每拍各 1 次 |

## 六、攻防接口（与决斗制对接，本刀只定语义）

- **压舱石与战场边界（P3 落地）**：身份链/插件表住 host 侧实体记录，结构性无地址——游魂无论多能打都碰不到它们。游魂的可写域=守方沙箱内存全集（连接器+各插件），对每个沙箱读就是读写就是写（决斗宪法2 原样适用，无只读区）。插件内存与连接器内存同权可写——**改魂打插件**（游魂 duel_write 插件内存=直接改写防御器官的决策表）零新语义，现行 duel 原语扩展分区寻址即达。
- **换装/拔除（刀2）**：游魂打赢后的收尾动作扩展——payload 可携带新插件字节，宣告完成时世界代执行"拔 X 槽装 Y"（夺舍确认后世界执行既成事实的唯一保留动作，与换血收尾同款地位）。特洛伊木（攻方送来的器官在守方体内当内奸）=换装语义的自然推论。
- **插件被攻的间接路**：游魂把插件内存写成垃圾=器官痴呆（行为错乱但本体活着，操纵比杀死值钱的器官版）；写崩=器官死（P4：世界不重启，重挂归连接器）。

## 七、零代码玩家路线（机制层支撑）

- 模板=现成字节包：官方以玩家身份供给示例插件（#011 合宪解法 B，官方示例内容路线）；玩家间分发插件包=文件拷贝，世界零参与（无内置商店——那是官方示例站的事，非世界功能）。
- 驾驶台阶：操控玩（现有）→ 想自动化某个动作=去拿一个现成插件装上（不写整脑只挂一个器官）→ 想改器官行为=写第一行代码。台阶的每一级都有机制载体。
- 玩法层零预设：插件分工形态（战斗/防御/求生/侦察/侦察反侦察…）全是玩家长出来的，世界只给 mount 这个门。

## 八、同业先例对账（2026-10-24 三路调研，结构参考）

- **seL4 微内核**（sel4.org 白皮书）：最小内核只做隔离+IPC（PPC 保护过程调用）+生命周期，一切服务是用户态进程；capability 授权。映射：连接器=内核级（身份+插件表+生死），插件=用户态服务，import 面=capability。10kSLOC 级 TCB 论证"极小=可信任"——连接器极小的价值同构。
- **VSCode extension host**（进程隔离+激活事件+生命周期钩子+API 注入+崩溃隔离）：宿主崩溃扩展不连坐=插件崩溃不连坐本体的先例；lazily activated（激活事件）对应咱们的"装载后下一拍开始跑"；API 面版本化=将来的兼容议题（MVP 不做）。**反面**：其扩展宿主可重启扩展——咱们不采用（裁决 P4，重启权归连接器代码）。
- **Bukkit/Sponge/Fabric 热插拔地狱**（Sponge 论坛官方拒 /reload、Fabric #855 not_planned）：根因=注册表撤销+依赖链+初始化生命周期只走一遍。**咱们天然回避**：无注册表（意图流+世界结算，插件不留全局注册物）、无 init-once 生命周期（插件=每拍调用的纯反应体）、卸载=销毁内存无悬挂引用。这是架构红利，写进判据：**插件永不可向世界注册持续状态——一切持续状态住实体数据/世界表，插件只是行为的临时载体**。

## 九、否决清单（防重蹈）

- **否决：插件间通信总线/共享内存公告板**（MVP 及可预见期）：插件协作走"各自对世界 API 出力"涌现（战斗插件出刀、防御插件防守，本不需互相知道）；要深耦合=写进同一个插件。VSCode commands 式总线是世界替玩法修剧情（#038 修路不跑车的边界：插件间还不是"路"，是同一台机器的俩器官）。信号=玩家真实喊出"两器官要协商"再议。
- **否决：插件权限分级/裁剪 import 面**：家长制，一个沙箱一份权利（§三）。
- **否决：世界自动重启崩溃插件**：保姆服务，违 P4；重启=免费满血磨掉耗魂攻击的战果。
- **否决：插件 fuel 总账分摊**（一口锅喂多张嘴）：违私有制不借贷的家族一致性，且削掉"防御深度=器官们能烧多少"已定案语义。
- **否决：矢量合成多插件移动**：把意图改成力语义，超纲；合力=单插件内自己写。
- **否决：听鼠标插件**（裁决 P1）：违驾驶者免疫夺舍。
- **否决：进场目录新契约（plugins/ 子目录初始包）**：data 段自带字节+第一拍 mount 等价，少一条目录规则少一分世界规定性。
- **否决：插件持久内存**：器官记忆随会话（同本体沙箱内存语义），永生器官=新永生漏洞（D-019 同款教训：世界不保存就没人赖世界）。

- **刀0（本卡施工范围）：插件化本体基座**——mount/unmount 两 import、插件槽数据结构、fuel 分账、意图仲裁、生死语义、单体兼容回归锚（现有玩家零破坏）、api.md/net-protocol/decisions 三文档同步。验收=examples 出一个"连接器+1 插件"样本：连接器极小（life+mount），战斗行为全在插件，行为与单体版等价。
