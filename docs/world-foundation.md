# CodeWorld 世界基础设计 v1（存在性体系）

> 状态：定稿待土豆过目 · 2026-10-14
> 来源：土豆 1014 系列讨论（三态模型/城的身体大脑分离/AI接入/一个基座两扇门）
> 宪法依据：#011 能力归框架，玩法归玩家；本文档全部设计不得违反

## 〇、一句话总纲

**世界只提供"一个基座、两扇门、三张合同"。实体是唯一原语；玩家怎么活、造物怎么死、城怎么防，全部是玩家代码自己的事。**

## 一、一个基座：实体（Entity）

实体 = WASM 代码（沙箱内运行）+ 状态（坐标/生存点/外观）+ 产权链（creator 指针）。

- **所有实体能力统一**：动/打/探/造/接外部通道——不因出身（角色/造物/NPC/阵法）受限
- 造物可以再造造物（套娃合法，产权链向下延伸）
- 现有 A/D/H/S 生物在结构上已是标准实体，此基座已存在

## 二、两扇门：进场方式

### 门一：认证进场（玩家角色走这扇）
- **MVP 形态**：`players/` 目录。一个 `.wat` 文件 = 一名玩家。文件存在=在线信号；删除=下线
- 未来升级：网络登录（连接=在线信号），语义不变
- 进场后获得：一个角色实体（锚定自己的在线信号）

### 门二：代码 spawn（造物走这扇）
- 世界内任何代码实体可 spawn 新实体（花/建筑/NPC/阵法/化身）
- 机制已存在（PendingChange::Spawn），只需开放给玩家代码
- 出生即合法：父母的 spawn 权限就是凭证

## 三、三张合同：存在性由谁锚定

| 合同 | 锚 | 谁用 | 语义 |
|---|---|---|---|
| **在线锚** | 玩家的在线信号 | 角色默认 | 上线存在，下线经残影期消失 |
| **自治锚** | 实体自己的代码 | 花建筑NPC默认 | 寿命/死亡规则写在自己代码里，父母无关 |
| **连接锚** | 外部端点的连通性 | 阵法/AI-NPC | 离线跑本体逻辑；在线获实时注入/外算力 |

**合同是玩家可组合的，不是框架选项**：
- 选在线锚=普通玩家；下线时自动 spawn 睡觉躯体=选自治锚当地产商；永动+持续扣生存点=选连接锚的硬核玩法
- 唯一框架强制底线：**战斗残影期**——最近 30 拍内参与战斗的实体下线，一律残影 5 拍（可被攻击掠夺），防拔线逃课。此条不可豁免

## 四、城的设计推论（身体/大脑分离）

- 城墙/建筑/NPC 躯体 = 自治锚造物：城主下线照常存在、可被攻打
- NPC 行为逻辑 = 写在 NPC 自己代码里的自治部分（呆但 7×24 在岗）
- 城的阵法/实时指挥 = 连接锚：城主在线才增强
- **服务挂载自由**：服务（heal/商店/传送）可以挂在城墙（城主死城仍在，可攻占继承）或挂在城主灵魂（我死城毁，焦土战略）——建造者的架构选择，框架不裁判
- 攻占 = 攻击覆写核心建筑代码（夺舍既有机制）；继承 = 产权链转让

## 五、外部通道（external channel）——通用能力

实体可声明一个由创造者控制的外部端点，世界转发特定事件，断连自动降级：

```
实体代码声明端点 → 世界转发事件（对话请求/阵法决策/任意自定义）
  ├─ 在线：请求送达创造者后端（大模型/算力农场/指挥中心），数拍后回包注入
  └─ 断连/超时：降级本体代码逻辑，实体不死只变"呆"
```

- **付费方=创造者**（他给 NPC 接大模型是他的成本）→ 天然氪金生态位
- **延迟即拟人**：当拍本体先回保底话术，AI 回包后补说——行业实测云 LLM 往返 3-7 秒，正好当"想一想说"
- 阵法接算力、NPC 接大模型、城接实时指挥：**一个接口三种用法**

## 六、安全底线（框架的诚实义务）

1. WASM 沙箱隔离 + fuel 限额 + import 白名单（已有，持续）
2. 外部通道：世界只转发，不执行外部返回的任意代码注入到宿主进程——外部内容只进入实体自己的沙箱
3. 战斗残影期（见三）
4. 攻击语义铁律 #001-004 不变；血条仅渲染层
