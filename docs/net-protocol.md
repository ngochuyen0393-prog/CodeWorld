## 1. 传输概要

| 项 | 值 |
|----|----|
| 协议 | WebSocket（升级自 HTTP） |
| 路径 | `/ws`（同源；静态页由同一端口 ServeDir 伺服）。**v2.9 起支持 `?token=<会话令牌>` 参数**（D-021f 凭据认领，见 §11；不带=观战连接）。**v2.2 起**另有 HTTP 通道：`POST /upload/avatar`（收图）+ `GET /assets/{id}.png`（原图直取）；**v3.0 起再加工坊 HTTP 通道**：`GET/POST/DELETE /api/player-code` + `GET/POST /api/bridge-config`（D-022b 起外桥可编辑，见 §12） |
| 端口 | `CODEWORLD_WS_PORT`，默认 8080；**0 = 禁用 WS**（纯终端模式，零开销） |
| 绑定 | 127.0.0.1（仅本机浏览器可访问；局域网观战留后续） |
| 方向 | 双向：下行=每拍全量快照推送；上行=客户端意图消息（v1.2 起） |
| 频率 | 下行每拍一帧（`CODEWORLD_TICK_MS` 默认 1000ms 一拍）；上行事件驱动（点击/按键即发） |
| 帧格式 | JSON 文本（`Message::Text`），下行全量快照（非增量），上行小消息 |
| 积压策略 | 下行慢客户端丢旧帧（后值覆盖语义）；上行尽力而为（非法/观战连接消息丢弃） |

## 2. 顶层字段

```json
{
  "tick": 42,
  "caption": "tick=42 | A->D dist=2.4 | D shield=7 | alive=3 | ctrl:P",
  "viewport": {"x0": -50.0, "y0": -25.0, "w": 100.0, "h": 50.0},
  "entities": [ ... ],
  "terrain": {"x0": -50.0, "dx": 0.25, "heights": [0.0, 0.13, ...]},
  "attacks": [ {"attacker": "uuid", "target": "uuid", "x": 15.0, "y": 0.5} ],
  "fields": [ {"x": 15.0, "y": 0.5, "radius": 3.0, "formed": true} ],
  "player_events": [ {"seq": 7, "tick": 42, "entity_id": "uuid", "kind": "born", "x": 40.0, "y": 0.0, "glyph": "塔", "lifespan_ticks": 10000, "name": "箭塔"} ],
  "events_cursor": 7
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `tick` | u64 | 世界当前拍数（WorldState::tick） |
| `caption` | string | 终端第 1 行战况字幕原文（含 `ctrl:` 操控段，#024 三态） |
| `viewport` | object | 世界坐标→画布坐标换算基准（见 §4） |
| `entities` | array | 全部存活实体的快照（含残影），按 `id` 字典序**稳定排列** |
| `terrain` | object | **地形折线投影**（v1.6 期 D-016 落地，本行为补登）：**仅起伏世界携带**（`CODEWORLD_TERRAIN=hills\|mountain` 起），`{x0, dx, heights}`——x0=首采样点世界 x（-50），dx=采样间距格（0.25），heights=各采样点地面高度数组（覆盖全域 401 点，高度∈[-幅度,+幅度]）；**平地世界/旧协议无此字段**（null 缺席省带宽，前端回落 y=0 水平地面）。物理/坐标语义以 crates/core terrain.rs 为权威，快照字段只是前端画地面贴图（草带+泥土剖面）的投影 |
| `attacks` | array | **本拍攻击命中事件**（v2.0，D-017）：结算成功的刀的三件套，空数组恒有 |
| `fields` | array | **力场环投影**（v2.3，D-012 可视铁律）：每条=场源坐标+场域半径+成型态；空数组恒有。`formed=false`=成型中（前端画虚线环，给进攻方反应窗），`true`=已成型（实线环）。场源造物本体照常在 entities 里，fields 层只画"可见气流环"（半透明描边，温迪气流环范本） |
| `player_events` | array | **本拍玩家事件**（v2.5，D-020a，见 §3.3）：增量事件流（新闻不是档案，只随当拍快照发一次），**已按操控玩家过滤**（可见性铁律：只发归属=操控玩家的事件 + 无主 compile_failed；空数组恒有） |
| `events_cursor` | u64 | **事件游标**（v2.5，D-020a）：世界已发出的最大 `seq`。断线对账用：前端以 `events_cursor − 本地已收 seq` 估算断线期间丢失的事件数（MVP 断线即丢不回放，见 §3.3 补拉口径） |

## 3. 实体字段

| 字段 | 类型 | 出现条件 | 说明 |
|------|------|----------|------|
| `id` | string | 恒有 | 实体 UUID（连字符小写）；帧内排序键 |
| `glyph` | string | 恒有 | ASCII 字形（与终端渲染同源） |
| `color` | string | 恒有 | 颜色名（red/cyan/yellow/purple/green/magenta/blue/white） |
| `x`, `y` | f64 | 恒有 | 世界坐标（f64 原值，未取整；画布换算见 §4）。活动实体 y ≥ radius（圆心即位置，脚贴地）；creation 落地 y=0（占地格贴地） |
| `radius` | f64 | 恒有（v1.5 起，#030） | 活动实体身体圆半径（默认 0.5；合法域 0.05..=25.0）——前端按它画身体圆轮廓。**creation（static）不用它**（身体=占地格 AABB：`floor(x)..floor(x)+1 × floor(y)..floor(y)+1`，前端按 kind=creation 画方格底衬）；**creation_dynamic（v2.1，D-003）身体=此半径的圆**，渲染/点击同活动实体 |
| `kind` | string | 恒有 | `"npc"` / `"player"` / `"creation"` / `"creation_dynamic"`（v2.1 起，见 §3.1） / `"projectile"` |
| `name` | string | 恒有（v1.1 起，原仅 player） | 显示名。**v3.1 起造物实名优先（D-020b）**：creation/creation_dynamic=`creation_name` 实名（spawn 第 24 参声明，如"箭塔"），缺省回退 `"造物#<8位短id>"`（旧存档/无名造物）；其余照旧 code_hash 原文：npc=`attacker`/`defender`/`hunter`/`spy`；player=玩家名（players/ 文件名）。前端控制台播报/造物列表/技能栏都显示它，十六进制 id 降级为悬浮 tooltip |
| `controlled` | bool | 仅 player | `true` = me 声明的操控目标（#024，每拍解析）；player 字段恒在（前端 `e.controlled` 直接可用） |
| `disposition` | string | 处置中的 player（v1.7 起，#025） | 会话级下线处置状态签：`"dispose_wait"`（处置等待中，操控连接意外断开倒计时）/ `"auto"`（停留+自主接管，on_tick 恢复）/ `"ai-await"`（停留+等外部 AI 接入，站桩）。**字段缺席 = online 在线态**（操控独占照常） |
| `wait_left` | u64 | 仅 `disposition="dispose_wait"` | 处置等待剩余拍数（每拍 -1，到 0 即被服务器默认带走）——前端画"处置等待中 NN 拍"抢救倒计时 |
| `owner` | string | 仅 creation/creation_dynamic | 创造者 PlayerId 的 UUID 字符串（产权链 #015） |
| `asset_ids` | string[] | **恒有（v2.4 起，#051 皮入沙箱）** | 沙箱装戴清单指纹（asset_id 列表，`av_`+16hex）；空盒=空数组恒有（前端零可选分支，同 attacks/fields 先例）。**快照只带指纹不带货**——前端首见按 id 走 `GET /assets/avatars/{id}.png` 取图入缓存（已见 id 复用缓存，同图全局一份）；取图失败/未加载 → 回落默认身体圆+glyph 渲染（VRChat 替身兜底），前端零阻塞。见 §9.4 |
| `born_tick` | u64 | **恒有（v2.5 起，D-020a）** | 出生拍（created_tick）——控制台造物列表算剩余寿命用 |
| `lifespan_ticks` | u64 | **恒有（v2.5 起，D-020a）** | 声明寿命（spawn 第 23 参落库值；0=永生，仅存量快照实体）——剩余 = lifespan − (当前拍 − born)，剩 ≤10 拍前端黄色警示 |

### 3.3 玩家事件字段（v2.5，D-020a）

顶层 `player_events` 数组，每条 = 本拍发生的、**归属操控玩家**（或无主 compile_failed）的一条事件。事件是新闻不是档案：只随当拍快照发一次，不跨拍滞留、无观众丢弃。**服务端过滤后再广播**（decisions #054 可见性同族）：归属=事件主体沿产权链（本体 code_hash 即在线玩家名 / 造物沿 bound_to 找主人）解析到的玩家名；拿不准归属的一律不发（宁缺勿泄）。六类 kind 与 payload 见 api.md「五点九、玩家事件流」；公共字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `seq` | u64 | 世界单调递增事件号（EntitySandboxMap 计数器；断线对账游标） |
| `tick` | u64 | 事件发生拍 |
| `entity_id` | string | 事件主体实体 UUID（compile_failed 无主体=空串） |
| `kind` | string | `spawn_rejected` / `compile_failed` / `runtime_error` / `born` / `died` / `player_log` / `player_joined` / `create_player_rejected`（后两类 v2.6，D-021b：无主公共新闻，entity_id=空串）/ `player_selected {name}` / `select_player_rejected {reason}`（后两类 v2.7，D-021d：无主公共新闻，登录/选角页回执，entity_id=空串） |

**断线补拉口径（MVP 选 B）**：断线即丢不回放；前端按 `events_cursor − 本地已收 seq` 估算丢失数，断线横幅提示"断线期间约 N 条事件未收到"。（A 档=服务端环形缓冲 256 条重连首帧回放，将来带宽富余再议——服务端不做每连接游标账本。）

**实名播报（v3.1，D-020b）**：born 带 `name`（实体显示名）；died 带 `name`（死者显示名——死者已出快照实体表，前端 join 不到，必须服务端带）且 `killer` 从实体 UUID 改为**显示名**（凶手是玩家→玩家名；是造物→造物实名；查无此实体→8 位短 id 兜底）。前端播报格式：`【箭塔】诞生 (x,y) · 声明寿命 N 拍` / `【箭塔】被击杀（凶手【测试】）`。

npc 实体**没有** `controlled`/`owner` 键（`skip_serializing_if` 保持 JSON 干净）；v1.1 起 `name` 全实体恒有（第二刀悬浮提示需要 npc 的代码身份）。

### 3.2 攻击命中事件字段（v2.0，D-017 协议小刀）

顶层 `attacks` 数组，每条=本拍**结算成功**的刀（击杀或击晕都算命中）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `attacker` | string | 攻方实体 UUID（与 `entities[].id` 同格式，前端可 join 找实体） |
| `target` | string | 目标实体 UUID |
| `x`, `y` | f64 | **目标位置=结算时刻实况坐标**（非攻击点击坐标）——前端动画包方向变体（attack_high/mid/low）的选槽依据 |

语义边界：**落空（点不在身体内/距离不足）/拦截/作废（攻击者已死/防守失败）不进广播**——拦截是防守方隐私，世界不替攻方宣布"打中了"；落空提示前端已有本地预告（v1.8 灰线）。事件随本拍快照一次性广播（事件是新闻不是档案，不跨拍滞留）；无观众=丢弃（零开销路径与快照同款）。

### v2.1 变更记录（2026-10-20，D-003 motion 出生声明）

- `kind` 新增 `"creation_dynamic"`：`code_hash="creation"` 且 motion=1 的全活造物（spawn 第 10 参声明，dev-plan D-003）——身体=声明 `radius` 的圆（不再是格对齐 AABB），出生拍起受完整物理（重力落点/阻力/极速钳制），渲染与点击判定同活动实体。
- `creation`（static）语义零变更：AABB 身体、方格底衬、AABB 点击包含判定，全现状。
- `owner` 字段出现条件从「仅 creation」扩为「creation/creation_dynamic」（产权链与运动身份正交，两档都带）。
- `radius` 字段对 creation_dynamic 开始有物理含义（=身体圆半径），对 creation（static）仍仅快照携带。

### v1.1 变更记录（2026-10-15，期四第二刀）

- `name` 字段出现条件从「仅 player」扩为「恒有」，值为 `code_hash` 原文。原因：Canvas 页悬浮提示要显示 name/kind，npc（A/D/H/S 主角四人组）在 v1 下无名可显；`code_hash` 即代码身份（本世界"代码即现实"的第一身份），恒有后前端无需可选分支。
- 其余字段与语义零变更；player 的 `name` 值不变（仍=玩家名）。

### 3.1 kind 判定（code_hash 纯映射）

| code_hash | kind |
|-----------|------|
| `attacker` / `defender` / `hunter` / `spy` | `npc`（开局四生物） |

## 4. viewport 换算基准

```json
{"x0": -50.0, "y0": -25.0, "w": 100.0, "h": 50.0}
```

- `x0`/`y0`：视口**左下角**世界坐标；`w`/`h`：世界坐标宽高
- 与终端渲染视口同源（`Viewport::world_x_range/y_range`），随 `CODEWORLD_VIEWPORT_*` 配置变化
- 画布换算（第二刀用）：`canvas_x = (entity.x - x0) / w * canvas_w`；
  注意世界 y 向上、屏幕 y 向下时需翻转：`canvas_y = canvas_h - (entity.y - y0) / h * canvas_h`
- 当前值域：x ∈ [-50, 50]，y ∈ [-25, 25]（默认配置）

## 5. 连接生命周期

| 事件 | 服务器行为 |
|------|-----------|
| 连接建立 | info 日志，订阅快照广播；**v2.2 起服务器先主动推一条 `avatar_assets` 一次性资产全量消息（首帧恒为它），v2.7 起紧接着再推一条 `player_roster` 一次性角色列表（见 §10；v2.8 起列表=本机角色档案过滤后的角色），快照从下一帧起**；**v2.9 起操控权凭会话令牌认领（`?token=` 命中会话表=操控连接，不在=观战连接+立即单播 `control_revoked{stale}`；不带 token=观战连接。逃生门：`CODEWORLD_ME` env 锁定时保留旧"第一连接=操控"）**——详见 §11（v1.2 的"第一连接=操控端"在 v2.9 退役） |
| 无浏览器连接 | 主循环跳过快照组装（零开销，不序列化不发） |
| 客户端 Ping | 回 Pong（载荷原样） |
| 操控连接文本 | 解析为意图入共享队列（与终端键盘同一条 mpsc，input.rs 单入口） |
| 操控连接 logout | **令牌立即失效（会话表移除，token 不得复用）+ 操控权释放 + 本连接降级观战**（v1.7，#025；v2.9 增 token 失效）：处置由 tick 侧落地；降级后下行快照照收（登出后世界还能看），上行丢弃 |
| 观战连接文本 | warn 丢弃（非操控端，v1.2；v2.9 起观战=无有效凭据的连接） |
| 非法上行消息 | warn 丢弃，连接不断（后续合法消息照常转发） |
| 操控连接断开 | 操控权释放；**v1.7 起：非登出的意外断开同时触发处置等待**（me 声明玩家留场 `CODEWORLD_DISPOSE_WAIT` 拍，默认 30，可被攻击，重连取消，超时默认带走）；观战连接断开仅清理资源。**v2.9：重连凭同一 token 重新认领（刷新页面不丢操控）** |
| WS 线程异常/端口占用 | warn 一次，终端世界照常运行（线程隔离） |
| （预留，未实现）`{"type":"shutdown"}` | **v1.9 注记**：WS 关世界接口预留——世界关闭的正规路径 MVP 只做终端 Q 二段确认（#036）；若将来开放，仅本机 localhost 操控连接允许，服务器存档+退出全体。本版收到 `{"type":"shutdown"}` 按未知 type 丢弃 |

## 6. 上行意图协议（v1.2 新增，#027；v1.7 增 logout，#025；v1.9 增 shoot，#036；v2.5 增 skill，D-020a；v2.6 增 create_player，D-021b；v2.7 增 select_player，D-021d；v2.9 起 select/create 附带会话令牌颁发）

客户端 → 服务器 JSON 文本消息，八型。坐标一律**世界坐标**（快照 viewport 域内）。

### 6.1 消息格式

```json
{"type": "move", "x": 12.0, "y": 0.0}        // 点击世界坐标 → 持续走位目标
{"type": "attack", "x": 15.0, "y": 0.0}      // 点击敌人坐标 → 单次出刀
{"type": "shoot", "x": 15.0, "y": 0.0}       // 点击远处敌人 → 操控射击（v1.9，#036；#045 起弹=定装 spawn 造物弹，见 6.2 与版本史退役口径）
{"type": "stop"}                              // 清除走位目标，站住
{"type": "logout", "disposition": "stay_auto"} // 登出处置三选一（v1.7，#025）
```

### 6.2 语义（服务器裁决，薄客户端 #026）

| 消息 | 语义 |
|------|------|
| `move` | 持续目标：操控实体每拍向目标走一步（半径碰撞裁决照常，不豁免物理）。**v1.5 矢量步**（#030）：步长恒 1.0 朝目标矢量方向（`dx,dy` 归一化 ×1.0——**斜走一步到位，v1.2/v1.4 的先横后竖与垂直优先废除**）；剩余距离 ≤1.0 时一步精确踏上目标（防到达容差带两侧振荡）；到达判定 = 与目标格距 **≤ 0.5**（含 0.5 防振荡）——到达地面目标清除站住，到达空中目标**不清除**（转悬停）。**悬停独立**（升力与移动解耦）：aerial 步（实体悬空 `y > radius` 或目标在空中）时服务器把实体放进本拍免重力集合——**移动被挡/滑动/出刀时升力照出，被挡≠坠落**（v1.4 的 +9.8 喷气补偿 hack 退役）。被身体挡下时**分轴滑动**：先试整步，撞则试 `(new_x, old_y)`，再试 `(old_x, new_y)`，都撞则原地贴墙（不推挤）；贴着的实体由接触边沿触发报告（不刷屏） |
| `attack` | 单次出刀：对点击坐标出刀（服务器点命中制 #031：点落在实体身体内即命中——圆=距圆心 < radius 严格、creation=格对齐 AABB 内；半径内多个命中取最近者，同距按 EntityId 升序定序）。与键盘空格走同一两阶段结算通路（操控不豁免物理，宪法）。**悬停中出刀不掉**（升力独立）：悬空实体攻击拍仍进免重力集合，位置稳定不坠落 |
| `shoot` | **操控射击（v1.9，#036；#045 弹丸退役后世界侧换载具）**：操控目标向目标方向发射一发**定装造物弹**——世界不再配发弹丸身体（#045 修路不跑车），改为解算器 `solve_launch_vector` 解出初速后 **spawn 一个 dynamic 造物**（小圆点 0.15/同款质量/unbound），出生点沿发射方向外推出膛，命中归接触通道（on_contact 代码攻）。初速解算=速度梯搜索（基准 12 封顶 22）+真实物理步序逐拍模拟（重力→阻力→极速钳→中点位移），无解不发射（服务器侧不发射+INFO，前端同判据不发消息）。**自定义弹道**：env.shoot 已随 #045 退役——玩家代码用 spawn 第 11/12 参出生初速自己拼（教学模板 docs/newbie-first-thrower.md）。**每拍 1 发限流沿用**（同拍多次点击后到覆盖先到，恰 1 发）。**与 move 并存**（边走边射）：shoot 不清除走位目标，射击拍不移动、下拍恢复走位；悬空射击照常免重力（升力独立） |
| `stop` | 清除走位目标站住（#025 操控独占的"我不动"）。**v1.4 起：stop 在空中 = 悬停不坠**（stop 语义是"停止移动"不是"坠落"；悬停锚点改写为脚下坐标，要落地玩家点地面）。前端由右键（contextmenu）或 S 键产生 |
| `logout` | **主动登出三选一**（v1.7，#025 下线处置权；仅操控连接生效，观战连接照旧丢弃）：`disposition` 取 `take`（带走：角色立即移除，文件锚保留，重连认领=重新进场重生）/ `stay_auto`（停留+自主接管：on_tick 恢复，角色自己活，重连=接管者被顶掉）/ `stay_ai`（停留+AI 待接入：站桩等外部 AI，端点协议是 #014 未来端点本刀不实现）。服务器收即释放操控令牌、连接降级观战（快照照收）；**处置中的玩家不被 me 声明重认领**——抢回操控必须走重连认领（操控权=me 声明+连接在，#024 精神） |
| `skill` | **技能栏**（v2.5 立项，D-020a；**v3.1 D-020b 语义重定义**）：`slot`=**该玩家技能格下标 1..9**（格=玩家 spawn 成功的造物模板清单，同名合并保留首次，上限 9；按格上行=服务端取出模板重新 spawn，出生点=操控实体旁 r+0.7，#030 预检/上限/编译全适用，失败走 spawn_rejected 事件闭环）。**技能=我的造物非预置清单**（v3.1 起预置四技能退役，`GET /skills/*.wat` 同退）；空格/越界 warn 丢弃。出生点=操控实体东侧身位偏移；**每实体每拍 1 发**（同拍连按只发第一发，再按报 RATE_LIMITED 事件）。非法槽位（0/10+/缺参）解析层拒绝丢弃。详见 api.md「五点十、技能栏」 |
| `create_player` | **进场仪式**（v2.6，D-021b）：`name`+`template`（blank/grazer/hunter 三选）→ 服务器写 `players/<name>.wat`（内容=模板全文，`GET /templates/<id>.wat` 同源）→ **当拍进场**（不等目录轮询）→ 写 `players/me.txt`（操控接管；`CODEWORLD_ME` 显式设置时不覆盖）。回执走 player_events 公共新闻：成功=`player_joined {name}`（面板收起+出生横幅），失败=`create_player_rejected {reason}`（NAME_EMPTY/NAME_TOO_LONG/NAME_BAD_CHAR/NAME_TAKEN/TEMPLATE_MISSING/IO_ERROR，红字回执）。名字校验的权威闸门在服务器 tick 侧（R1 复审改法 B：解析层不做名字校验——Err 分支=静默丢弃无回执，前端 busy 锁会挂死；全部拒绝统一走事件回执，含格式类 NAME_* 三码）。**v2.7 起：任意连接生效**（登出后的观战连接也要能新建——旧"仅操控连接生效"作废）。**v2.9 起：服务器收到即颁发会话令牌**（当场单播 `session_token {token,name}`，成功路径绑定进会话表——重连/刷新凭它认领操控，见 §11）。**首启归档**：空世界模式+空玩家目录启动时旧 db 挪 `archive/`（启动瞬间做——sqlite 句柄锁 db，进程内挪不动；create_player 链路永不碰 db）。详见 api.md「进场仪式」节 |
| `select_player` | **选角进场**（v2.7，D-021d 登录/选角页）：`name` 必须在 `players/` 有 `.wat`（文件锚=身份）→ 覆写 `players/me.txt` 为单行该名字（#024 契约，等价 me 声明）→ 清该名字的 absent 离场标记（登出带走后选角=下拍扫描重生角色）+ 处置状态（接管者被顶掉）+ 编译失败黑名单（显式选择=允许重试一次，失败会重新拉黑）→ 回执 `player_selected {name}`（前端收到**才**断开重连——重连带 token=凭据认领操控，v2.9）。拒绝回执 `select_player_rejected {reason}`：`NAME_UNKNOWN`（players/ 无此角色）/ `ME_ENV_LOCKED`（`CODEWORLD_ME` 环境变量已设——env 锁定优先于一切 me 声明，诚实拒绝）/ `IO_ERROR`（me.txt 写失败）。**任意连接生效**（登出后的观战连接是登录页的选角通道）。**v2.9 起：服务器收到即颁发会话令牌**（同 create_player，见 §11）。me.txt 契约一字不动（单行玩家名；`CODEWORLD_ME` 优先级不变） |

### 6.3 冲突与状态规则

- **同拍互斥，后到优先**：同一拍内键盘意图与鼠标意图按到达顺序折叠，最后的意图生效（点敌人后同拍点地=走路生效；先点地后点敌人=出刀/出弹生效）
- **shoot 不清除走位目标**（v1.9，#036）：远程射击与走位目标独立并存（边走边射——射击拍不移动，下拍继续向目标走）；与 attack 同语义
- **键盘接管清除走位目标**：按键移动 = 玩家接管脚下，`move` 持续目标被清除（松键不会复活旧走位）。**v1.5：悬停中按方向键 = 飞行操控**（升力随实体悬空状态：W 爬升 / S 降落 / A/D 平移，松键无行动拍重力接管=坠落，先 stop 再悬停）
- **attack 不清除走位目标**：单刀与走位目标独立并存（悬停中出刀不掉，见 6.2 升力独立）
- **悬停持续到新意图**（v1.4 承继，v1.5 机制改免重力集合）：move 到空中点后 P 留在空中（每拍悬停意图，#029 无税）；新 move 改向 / stop 锚定脚下 / 键盘接管清除目标（清除后无行动拍=坠落，物理照常）
- **操控死亡/下线 = 升力停止**：意图侧状态（走位目标/飞行相位）清零，坠落由物理接管（落点解析：地面=半径线，落在别的实体身上=接触即停，堆叠合法——底下的走了上面的自然下落）
- **目标不跨角色交接**：操控目标变更（换声明/重进场）时旧走位目标清除；观战/无操控拍目标同样清除
- **点击自己**：前端命中判定排除操控目标自身（不出刀）；点自己脚下按 move 处理（立即到达=站住，无害）
- **选中容差 1.5**（v1.6，期四第七刀）：前端点击命中判定放宽——活动实体=距圆心 **< 1.5 格**即选中（多命中取最近；不必点得极准）；creation 仍 AABB 判定**不吃容差**。服务器 attack 结算不变（#031 点命中制）：命中消息带实体快照坐标，点在身体内才真命中——容差只放宽"选谁"，不改变"打不打得中"
- **点击实体用快照坐标**：攻击坐标取自插值显示的实体坐标（可能滞后 ≤1.5 拍，可接受；实体若已走开超半径则落空——移动目标打不中，站桩目标必中）
- **贴障停滞清目标**（v1.6，期四第七刀）：走位目标被身体挡死时（2 拍窗口净位移 < 0.01 格：全挡原地或"终进近步被挡滑出又滑回"的 ±0.08 乒乓蹭动），服务器视为到达、自动清除走位目标站住——P 不会贴着障碍逐拍蹭动。前端收到后续快照自然站定，无需客户端处理

### 6.4 操控权认领（v2.9 凭据制；#024 独占不变，v1.2-v2.8 为"第一连接=操控端"）

- **操控权凭会话令牌认领**（v2.9，D-021f）：连接 URL 带 `?token=` 且命中服务器会话表 → 该连接=操控连接（上行意图生效）；不命中 → 观战连接+立即单播 `control_revoked {reason:"stale"}`；不带 token → 观战连接。**同 token 再次认领会踢掉旧连接**（`control_revoked {reason:"taken"}`，被踢者降观战不断连）——同凭据攻防互换，Screeps token 认人不认网线 / 暴雪同账号新登录踢旧会话的同款语义。**逃生门：`CODEWORLD_ME` env 锁定时保留旧"第一连接=操控端"**（开发者场景 loginSkip 不重连也保有操控）
- **#024 独占不变**：任意时刻至多一个操控连接，变的只是钥匙（先来者得 → 凭据者得）；操控连接断开 → 操控权释放（处置等待照旧，#025）
- **v2.7 会话动作任意连接生效**：`create_player`/`select_player` 在观战连接也生效（登录页=观战连接的进场通道，落地拒绝归 tick 侧事件回执）
- **v1.7 令牌语义（#025；v2.9 增会话令牌失效）**：主动登出（logout 消息）= 操控权立即释放 + 本连接的会话令牌从表移除（不得复用，刷新后重新登录页选角），本连接降级观战（世界继续直播）
- **两条下线路径并存不互相踩**：文件锚删除（删 players/*.wat）= 账号级下线，走残影旧路（#013）；登出/意外断开 = 会话级下线，走处置状态机（#025）。文件删除时处置状态让位残影路径
- **WS 连接 ≠ 操控权**：意图能否作用于角色仍由服务器侧 me 声明（`CODEWORLD_ME` / `players/me.txt`，#024）裁决——会话令牌是 me.txt 声明的连接版凭据（v1.2-v2.8 的"本机浏览器=我第一连接"等价物退役）
- 升级路径：多人/认证留后（token=随机凭据非密码，多人时代换轨账号体系）

## 7. 客户端预测与和解（v1.3 新增，期四第四刀）

浏览器对**自己发出的** `move`/`stop` 意图做本地预测（Valve 标准组合：己方预测+他人插值），
消除"点击后 1-2 拍才动"的观感。协议消息零变更——预测纯前端行为，服务器照旧全权裁决。

### 7.1 预测规则（镜像铁律）

- 前端 `applyMoveSteps`（static/index.html 纯逻辑区）与服务器 `next_move_step`
  （bin/codeworld/src/input.rs）是同一规则的 JS/Rust 双实现，v1.5 矢量步化后：
  - 步长恒 1.0 朝目标矢量方向（`dx,dy` 归一化 ×1.0，斜走一步到位——先横后竖
    与垂直优先废除）；
  - 剩余距离 ≤1.0 时一步精确踏上目标（防到达容差带两侧永久振荡）；
  - 格距平方 ≤0.25（格距 ≤0.5）到达即停（地面清目标 / 空中悬停位置冻结）；
  - 落地钳半径线 0.5（镜像服务器地面约束：圆心即位置，脚贴地）。
  - **镜像建模的是意图路径**（无阻挡理想轨迹）：服务器的分轴滑动/被挡/外力
    由和解对账纠偏（分歧瞬移回服务器真实坐标），0.25 格对账阈值覆盖浮点噪声。
  - **停滞清目标不进镜像**（v1.6）：贴障停滞检测是服务器裁决语义（预测不知道
    自己被挡）；预测照常外推，靠快照和解纠偏站定并清本地目标。
- **改一处必须同步另一处**（本节即契约锚点）；键盘/终端来源的意图不预测——
  前端只对自己发出的 move/stop 建预测。stop 在空中 = 冻结当前预测位置（服务器
  悬停零位移，快照确认后回落插值）。

### 7.2 预测模型（锚点外推）

- 点击 move 时：预测锚点 = 最新快照的 P 服务器坐标，锚点拍号 = 快照 tick + 1
  （意图下一拍 drain 消费：首个确认帧应零位移，此后每帧一步）。
- 渲染：从锚点按镜像规则外推，进行中的一拍乐观先走一步（点击瞬间 P 就动）。
- `stop`：冻结当前预测位置（立即站住），待快照确认站定后回落插值。

### 7.3 和解（每帧快照对账）

- 一致（预期位置与服务器坐标距离 **< 0.25 格**）→ 预测确认，锚点前移至该帧。
- 分歧（被挡/被外力移动/意图未生效如观战连接）→ P 瞬移回服务器真实坐标
  （渲染回落插值采样，玩家可见校正），清除本地 move 目标与虚线，预测状态清空。
- P 死亡（快照无 controlled 实体）或断线重连 → 清全部预测状态。
- 他人实体照旧走快照插值，不受预测影响。

### 7.4 断线冻结（v1.9 新增，#036 期五第五刀——前端行为契约）

与世界失联（WS 断开，含世界进程被杀）时，浏览器进入**冻结态**——诚实的失联画面：

- **预测冻结**：断线即清全部预测态（predTarget/predAnchor/predHold/moveTarget），
  P 停在最后服务器确认位置（插值缓冲钳在最后一帧快照，画面静止但不消失）。
- **点击门控**：断线（bad）与连接中（wait）状态下一律拦截画布点击——不发预测、
  不画虚线、无红框/弧线反馈、P 不动（纯函数 `canClick(connState)`，仅 `ok` 放行）。
  修正旧象：断线后点击仍驱动 P 本地"移动"的预测假象（画面骗人，违诚实原则）。
- **断线横幅**：顶部红色横幅「⚠ 与世界断开——重连中(第N次)」（N=断线重连计数，
  连上清零）；底栏连接状态同步显示退避秒数。画面其余照常渲染（最后一帧快照
  静止显示，世界没有"消失"）。
- **重连成功**：横幅消失、缓冲重建、操控恢复（既有 onopen 清理逻辑不变）。
- **已登出断线不受此契约约束**：logout 后连接断开=观战降级的正常态（世界直播
  已停是事实，不是假象），保留既有「已登出 · 连接已断」提示与「重新进入世界」
  入口，不弹断线横幅、不自动重连。

## 9. HTTP 收图通道 + avatar_assets 资产下发（v2.2，D-017 先行刀）

→ 128x128 位图掩码生成 → 一次性下发。世界只提供能力不解释图像内容（项目宪法）；

  | 字段 | 必填 | 说明 |
  |------|------|------|
  | `file` | 是 | PNG 字节（透明底角色图；≤2MB=MAX_AVATAR_PNG_BYTES，边长 ≤1024=MAX_AVATAR_PNG_DIM 恰等放行；调色板/灰度/16 位自动归一，真彩 RGBA/RGB 全收） |
  | `name` | 是 | 角色名（string，UTF-8；非空且 ≤64 字节，中文名合法） |
  | `height_world` | 否 | 世界高度格数 f64（默认 2.0，域钳制 0.05..=25.0——与 radius 域一致；本版只登记不消费，挂实体刀用） |
- 响应：**HTTP 恒 200**，成败看 JSON `ok` 字段：
  - 成功：`{"ok":true,"asset_id":"av_<16hex>"}`
  - 拒绝：`{"ok":false,"reason":"<枚举>"}`，reason 全 ASCII 小写：
    | reason | 触发 |
    |--------|------|
    | `bad_json` | multipart 缺 file/name 字段 / name 空或超 64 字节 / height_world 非数值 / 请求体解析失败 / **磁盘 IO 失败降级**（服务器 error 日志留痕，排查看日志） |
    | `oversize` | PNG 超 2MB |
    | `oversize_dim` | 原图边长超 1024（恰等放行另一侧） |
    | `decode_failed` | PNG 解码失败/截断/不支持格式 |
    | `isolate_fail` | 连通性校验失败：断件图（存在第二个面积 ≥ N=8 的连通域，或全空图） |
- 掩码管线（世界侧能力，常数入 game-menu 1.7 总账）：PNG 解码 → alpha 阈值化
  （**>50%** 算实心，`MASK_ALPHA_THRESHOLD`=127）→ area-average 降采样 128x128
  （块内实心占比**>50%** 算实心，`MASK_DOWNSAMPLE_THRESHOLD`=0.5 与上同值对称；
  块边界 floor(i·W/128) 精确划分，小图忠实放大=最近邻）→ 4-连通校验（主件=最大
  连通域；非主件面积 ≥ `MASK_FRAG_DROP_N`=8 **待拍板临时值**=断件打回；小碎片
  静默丢弃收图成功并记日志）
- 落盘：`assets/avatars/{asset_id}.png` + 伴生 `{asset_id}.json` 元数据
  （asset_id/name/height_world/w/h/created_tick——git 不入库；资产=静态文件，
  不进 SQLite 快照管线，启动扫目录重建登记表，坏文件 warn 跳过）
- 非 multipart 请求由 axum 内建 rejection 拒绝（非 200 文本体）

### 9.2 avatar_assets 消息（WS 连接首帧，一次性全量）

连接建立后服务器**主动**推一条（先于任何快照帧；重连重发幂等，前端整表换新）：

```json
{"type":"avatar_assets","assets":[
  {"asset_id":"av_0123456789abcdef",
   "url":"/assets/av_0123456789abcdef.png",
   "w":512,"h":512,
   "mask":[0,1,1,0,...]}
]}
```

| 字段 | 说明 |
|------|------|
| `assets` | 数组**恒有**（零资产=空数组，前端不必判消息缺失） |
| `asset_id` | 资产标识（`av_`+16 hex） |
| `url` | 原图 HTTP 直取路径（`/assets/{id}.png`；掩码走本消息、原图走 HTTP——前端按 w/h 纵横比渲染原图） |
| `w`,`h` | 原图尺寸（非 128 表尺寸） |
| `mask` | 128x128 布尔表行主序（0/1 共 16384 项） |

带宽注记：掩码 32KB JSON/资产，资产数预期少可全量——资产多时改增量（版本演进
预留已挂 §8）。`/assets` 由 ServeDir 伺服（axum nest 剥前缀：`/assets/{id}.png`
→ 资产目录内 `{id}.png`）。

### 9.4 快照 asset_ids 指纹 + 前端取图（v2.4，#051 皮入沙箱）

沙箱=一个盒子装三样：代码（引擎，wasm 模块）、数据（魂，线性内存）、**皮（美术
资产段，v2.4 新增）**。夺沙箱=夺全套。资产段=数据非执行：不烧 fuel、不参与编译
实例化、只占沙箱配额（引擎+魂+皮合计封顶，超限拒绝换血/装戴）。

- **快照侧**：`entities[].asset_ids`（恒有字段，空盒=空数组）——只带 asset_id
  指纹，不带货（世界只搬运不理解，修路不跑车）
- **取图路径**：前端首见某 asset_id → `GET /assets/avatars/{id}.png`（D-017 的
  ServeDir 同一目录）→ 缓存复用（同图全局一份，服务器侧镜像仓另有 sha256 指纹

- **替身兜底（VRChat 判例）**：资产未加载/加载失败 → 回落默认身体圆+glyph 渲染，
  前端零阻塞不重试（failed 状态缓存，本会话内恒兜底）
- **装戴/随行**：装戴清单由 host 写入沙箱资产段；换血（被攻击换代码）时资产段
  整体随行转移（夺沙箱=夺全套，无拆分选项）；沙箱亡=资产段亡；超配额的换血
  整次拒绝（资产不丢）。改皮战术：换血后新代码可改写资产段（金龙旗改黑龙旗=
  占领宣示）

## 10. player_roster 角色列表（v2.7，D-021d 登录/选角页；v2.8 私有化，D-021e）

登录/选角页的数据源：服务器把**本机角色档案（`players/.my-characters`）登记 ∩

```json
  {"name":"土豆","glyph":"土","color":"green","online":true},
```

## 11. 会话令牌：操控权随凭据走（v2.9，D-021f）

操控权认领的钥匙从"第一个连接"换为"会话令牌"——**#024 独占不变**（任意时刻仍只有
一个操控连接），变的只是钥匙（先来者得 → 凭据者得）。同行定案：Screeps token 认人
不认网线 / 暴雪同账号新登录踢旧会话 / WS 工程标准=会话令牌+重复连接守卫。

### 11.1 令牌生命周期

| 阶段 | 行为 |
|------|------|
| 颁发 | 服务器收到 `select_player`/`create_player` 上行即生成（uuid v4），**当场单播 `session_token` 给发起连接**（不等 tick 结果）+ 塞进 Intent |
| 绑定 | tick 侧落地**成功路径**才写会话表（token→玩家名）；拒绝路径该 token 永不绑定=自然无效（前端配合只在成功回执后才落盘） |
| 认领 | 连接升级验证：URL `?token=` 命中会话表 → 操控连接（踢旧沿：`send(Some(新连接id))`，旧操控端收到变化比对后降观战） |
| 失效 | ①logout=从表移除（登出=会话终结，token 不得复用）②世界进程重启=表清空（全部失效，重新登录页选角——单机阶段合理默认） |

### 11.2 下行帧：session_token（选角/创建后当场颁发）

```json
{"type":"session_token","token":"3f9a2c…","name":"土豆"}
```

| 字段 | 说明 |
|------|------|
| `token` | 会话令牌（uuid simple 格式 32 hex）；前端收到只暂存内存，**成功回执（`player_selected`/`player_joined` 按名匹配）才写 localStorage** |
| `name` | 该令牌对应角色名（前端按名匹配防"别人的令牌"误落盘） |

### 11.3 下行帧：control_revoked（操控权变动通知）

```json
{"type":"control_revoked","reason":"taken"}   // 被新凭据接管
{"type":"control_revoked","reason":"stale"}   // token 失效（过期/登出后/伪造）
```

| reason | 触发 | 本连接状态 | 前端动作 |
|--------|------|-----------|---------|
| `taken` | 带同 token 的新连接认领（踢旧沿） | 降观战，**连接不断**（下行快照照收，上行丢弃）；**token 保留**（刷新可抢回，同凭据攻防互换=暴雪语义） | 顶部横幅"你的操控已在别处接管" |
| `stale` | 连接所带 token 不在会话表（登出后/重启后/伪造） | 观战连接 | 清 localStorage 凭据 + 横幅"登录已过期，刷新页面重新选择角色" |

- 帧序：`stale` 在连接建立时紧随 `player_roster` 之后（第三帧）；`taken` 在踢旧沿
  触发时单播（可能在任何时刻）
- 认领方自己引发的沿（新值=自己）不触发 `taken`；被踢者再发上行=观战连接照旧丢弃
- 被踢后断开不触发操控权释放（操控权已属新连接，误发会错拆新操控端）

### 11.4 WS URL 参数

`GET /ws?token=<会话令牌>`——`token` 参数缺席=观战连接（legacy 逃生门除外）；
非法值/未知值按不命中处理（观战+stale 通知）。逃生门：`CODEWORLD_ME` env 启动时
非空 → 保留旧"第一连接=操控端"（开发者 env 锁定场景 loginSkip 不重连也保有操控），
此时无 token 连接的第一条仍认领操控。

### 11.5 前端配套（static/index.html）

- `connect()` 连接 URL 带 localStorage（键 `cw_session`，值 `{"token":..,"name":..}`）
  里的 token；localStorage 读写全 try/catch（隐私模式/Safari 阻断兜底：读失败=无
  token 观战，写失败=静默降级为每次重登录，不炸页面）
- 登出（logout 三选一）：清 `cw_session`（服务器已删 token，本地凭据一并清）——
  下次连接=全新观战 → 登录页
- 出生镜头：观战全景中选角完成 → 相机从当前视野中心起步（`CAM_LERP` 复用，零新
  常数）平滑飞向自己实体；从未渲染过=直接对准（旧行为）

## 12. 工坊 HTTP 通道（v3.0 基础 + D-022b 面板迁入/外桥可编辑小扩展）

玩家工作台=**世界页面内的侧滑面板**（D-022b 起：战场页底栏「🛠 工坊」/快捷键 B
开合，ESC 收起；workshop.html 新标签页已退役删除）的五个 HTTP 路由，全部挂 WS
同端口，HTTP 恒 200、成败看 body `ok` 字段（upload/avatar 同款约定）。工坊的 WS
是**无 token 观战连接**（收 player_events/player_roster 做列表与事件流，不发任何
上行意图，不需要操控权；主连接的 player_events 按操控玩家过滤，工坊独立连接看
全角色事件——谁的 compile_failed 都能标红定位）。核心语义：**玩家 .wat=热进场
——保存=写 `players/<名>.wat`，世界每拍目录轮询自动接手（新文件下拍进场、删除
下拍残影下线），零新进场协议**。

### 12.1 POST /api/player-code（工坊保存=进场通道）

- 请求：`application/json`，`{"name":"角色名","code":"WAT 全文"}`。
- 处理链：`sanitize_name`（唯一权威闸门，与 create_player 同源）→ 长度护栏
  （**256KB**，防滥用）→ 写 `players/<名>.wat`（**覆盖写**）→ 成功路径登记本机
  角色档案 `.my-characters`（与 create_player 成功路径同款——工坊角色列表数据源
  =player_roster，档案不登记则列表看不见）。**不写 me.txt**（造物/角色文件管理
  ≠操控声明）；**不手动 spawn**（进场靠目录轮询）。
- 响应：`{"ok":true}` / `{"ok":false,"reason":"<码>"}`：
  | reason | 触发 |
  |--------|------|
  | `BAD_JSON` | 请求体不是合法 JSON / 缺 name 或 code 字段 |
  | `NAME_EMPTY` / `NAME_TOO_LONG` / `NAME_BAD_CHAR` | 名字闸门（同 create_player） |
  | `CODE_TOO_LONG` | code 超 256KB |
  | `IO_ERROR` | 写盘失败（服务器 error 日志留痕） |
- 边界：**在线热替换不做**——目录轮询只看存在性，已进场玩家改文件不自动重载；
  在线角色保存成功但下次进场才生效（工坊面板有提示）。

### 12.2 GET /api/player-code?name=（工坊加载）

- 读 `players/<名>.wat` 全文 → `{"ok":true,"code":"..."}`。
- 拒绝：`NAME_*`（名字闸门）/ `NAME_UNKNOWN`（players/ 无此角色）/ `IO_ERROR`。

### 12.3 DELETE /api/player-code?name=（工坊删除）

- 删 `players/<名>.wat`（不存在=NAME_UNKNOWN）→ 世界下拍残影下线（既有语义，
  在线角色删除同理）。**不动 me.txt**。
- 拒绝：`NAME_*` / `NAME_UNKNOWN` / `IO_ERROR`。

### 12.4 GET/POST /api/bridge-config（外桥端点表读+写，D-022b 可编辑）

- **GET**：vault 装配 → `{"ok":true,"enabled":true,"ports":[{"port":1,
  "url":"http://127.0.0.1:9001","note":"外脑服务器"},...]}`（端口升序；url=
  编辑框回填用，D-022b 新增；note=bridges.json 人读字段原样透传，可空串）。
- GET 桥未启用（`CODEWORLD_BRIDGE` 未开）→ `{"ok":true,"enabled":false,
  "ports":[]}`（前端黄字提示桥未启用，仍可编辑保存——写盘即用，桥下次启用生效）。
- **POST**（D-022b 新增写通道）：请求 `application/json`，
  `{"ports":[{"port":1,"url":"http://127.0.0.1:9001","note":"外脑服务器"},...]}`。
  处理链：**整批校验**（与 load 装载校验同一套规则函数——port>0 且回环 host 且回复
  http；任一条非法=**整单拒绝**，文件一字不动）→ 读旧文件按 port 合并 headers
  （**凭证不落浏览器**：headers 不进 UI 不进请求体，已登记的鉴权头原样保留）→
  pretty JSON **原子写** bridges.json（临时文件同目录先落再换名，防写一半崩档）→
  vault 装配时写锁 reload 内存同步（`bridge_send` 下一拍按新表解析；主循环每拍
  mtime 热重载走同一把 RwLock，幂等无害）。
  - vault 未装配（桥未启用）POST 也受理：写盘成功即返回 ok（桥下次带
    `CODEWORLD_BRIDGE=1` 启动即用）。
  - 空数组=清空登记（文件落 `[]`）。
  - 响应：`{"ok":true}` / `{"ok":false,"reason":"<码>","index":<定位下标>}`：

  | reason | 触发 |
  |--------|------|
  | `BAD_JSON` | 请求体不是合法 JSON |
  | `PORT_INVALID` | 某条 port ≤ 0（index 指向第几条，0 起） |
  | `URL_INVALID` | 某条地址非法：https 拒（MVP 客户端只做本机 http）/ 非 http
    scheme / URL 解析失败 / host 非本机回环（仅 127.0.0.1/localhost，大小写
    不敏感）（index 同上） |
  | `IO_ERROR` | 写盘失败（服务器 warn 日志留痕；无 index） |

- 测试连接**不在协议面**：纯浏览器侧 `fetch(url, {method:'HEAD', mode:'no-cors'})`
  直连测可达（opaque 响应 resolve=可达，reject/3 秒超时=不通），零服务端参与。
