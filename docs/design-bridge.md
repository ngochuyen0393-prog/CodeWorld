## 一、桥是什么（一句话 + 心智模型）

**桥 = 世界给你开的一条对外邮路：你的沙箱代码往外发消息（信），你的外部服务器回信，世界照收照转，不看内容不代存。**

三句白话（讲解用）：
1. 你的造物（塔/弹/城）每拍想问外脑"往哪拐"，就写一封信发出去——世界只当邮差。
2. 外脑回信（"左转 30 度"），世界把信塞进你造物沙箱的收件箱，下一拍你的代码读到照做。
3. 谁的服务器、信里写什么、多久回一封——全是你自己定的，世界一个字不看也不管。

心智模型（对照既有概念）：
- 与 D-011 数据通道的关系：D-011 立法里"外桥覆盖弹丸沙箱"——本桥就是外桥的**对世界外出线段**；世界内沙箱↔沙箱的消息（D-011 数据通道的世界内段）另刀实施。两者共用"只送信不拆信"法条，管道分开。
- 与 bind 契约的区分：bind=出生时签的合同（条款刻在造物上，世界每拍照办，零通信）；桥=活电话（实时双向，按消息计）。D-011 链三件套里本桥实现"数据通道"件。
- 世界角色：邮局，不是翻译局——世界不提供"帮我算"的服务（architecture.md 里的 compute/call/TaskType 枚举草稿违 #011，第八节作废清单处置）。

## 二、通信模型（机制层核心）

### 2.1 消息协议（Wire protocol）

**设计基线：HTTP POST + JSON body，一次性短连接。**（理由见 2.4）

四方与端到端格式：
- **沙箱侧（发信）**：玩家代码调用 `bridge_send(port: i32, ptr: i32, len: i32) -> i32`。
  - `port` = 账号保险库里登记的外部端点别名（见 3.2），不是 URL——**沙箱永远拿不到服务器地址**（铁律①）。
  - `ptr/len` = 沙箱内存中 payload 起点/长度（任意字节 ≤ 8KB），世界不解释不审查。
  - 返回 i32：`0`=已排队；`1`=无此端点；`2`=payload 超限；`3`=在途满；`4`=桥未启用/已吊销。只表示"信进了邮筒"，不表示送达/已回复（异步跨拍，见 2.2）。
- **世界侧（搬运）**：出站管理器（独立线程）收到 bridge_send 意图 → 查保险库解析 port→URL+鉴权头 → 以世界进程身份发 HTTP POST → 等响应。
- **外部服务器侧（收信+回信）**：任意识 HTTP 的服务器（玩家自备：物理机/云函数/nginx/大模型代理/树莓派）。收到 POST，处理，HTTP 200 响应 body 即回信（任意字节 ≤ 8KB）。
- **沙箱侧（收信）**：新可选导出 `bridge_on_reply(port: i32, ptr: i32, len: i32)`。世界收到外部响应后写进发起沙箱的收件队列，下一拍 collect 阶段调用。

消息封装（世界发出去的 HTTP body 格式，玩家服务器解析用——世界侧生成，内容字段玻璃不透明；示例为实现形态，与 api.md bridge_send 词条一致）：
```text
BridgeEnvelope {
  "world": "codeworld",   // 世界标识（多世界时代用）
  "entity": "42",         // 发起实体 EntityId（十进制字符串——u128 数字 JSON/JS Number 装不下，parse 回整数对账）
  "port": 1,              // 端点别名
  "seq": 17,              // 单实体单调递增序号（玩家对账/去重用）
  "payload": [87,72,69]   // 原始字节 JSON 数组，世界不解释（base64 升级挂起，见 §2.8）
}
```
回信=纯 body（世界不做信封拆包——外部服务器想回什么回什么，世界原样投递，长度 ≤ 8KB）。

### 2.2 时序语义（拍制世界的异步桥，世界诚实的核心）

一拍=1 秒，桥不能"同步等"（同步 HTTP 会卡死世界循环）——**桥是异步的，跨拍往返**：

```text
拍 N    你的代码调 bridge_send —— 意图排队（本拍 on_tick 已在跑，与 attack 同款管线）
拍 N    出站管理器独立线程发 HTTP（不占世界循环，不等拍边界——早发早到）
拍 N+1 ~ N+K    外部服务器处理（网络+算力延迟，K≥1）
拍 N+K   响应回到世界 → 写进你的沙箱收件队列
拍 N+K+1  collect 阶段调 bridge_on_reply（拍边界，确定性锚）
```

最理想 N+2 拍读到回信（发信拍+回信拍）。**跨拍=外脑不送速度，送思考深度**（与燃料继任制"拖=攻方必先油尽"同款结论）：无桥时代跨拍续算只有 code 内状态机一条路（on_tick 手写多拍状态机，用 fuel 换深度）；有桥后多一条路=外部算力（网络延迟+自付成本换深度）。桥=多一条路，不是换掉世界规则——fuel 照烧/物理照跑/死亡照死。
- **速率天花板由拍频定死**：每沙箱每拍 1 发（2.5）——1 拍/秒时代每秒最多问 1 次；拍速升级（5~10拍/秒）落地时天花板自动抬高。不是桥的限制，是世界的节律。
- **超时/失败=诚实返回**：出站 5 秒超时或连接失败 → 不投递 bridge_on_reply（或投递空回信？**定案：不投递**——代码里自己记"我发过 seq=17 没收到回声"，超时逻辑归玩家）。世界不重试不代放弃。
- **离线退路（#029 明文）**：无端点/桥未启用/吊销中 → bridge_send 返回失败码，代码跑本地降级逻辑——离线/无外接=本体基础功能照跑；在线+外接=体系满血。降级策略归玩家代码。

### 2.3 拍内时点契约（与攻击时序契约同款纪律）

- **bridge_send 调用点**：on_tick 内任意时刻（与 attack_at 同款——意图排队，当拍不结算）。
- **bridge_on_reply 投递点**：collect 阶段（下一拍边界）——回信到达时刻在拍中任意点，但调用固定在拍边界（拍内任意点调沙箱破坏 #044 确定性红线）。与 on_attack 排队同款管线纪律。
- **死亡竞态（诚实世界，口径与实现对齐）**：信件在**世界出站时点**仍需发件人存活——出站前死亡（含同拍自尽）→ 信作废不送（INFO 日志，死者信不送）；已出站的信照飞不撤（"消息发出≠载体存活"（#038 濒死回传）的镜像条款：**载体不存活≠消息没发出**）；回信抵达时发件人已死 → 回信无人认领，丢弃+INFO 日志。三段竞态处置全带日志，不做"死前抢投"（世界不抢救玩家）。

### 2.4 传输选型（HTTP/JSON 嵌线；WS/gRPC/自定协议不作 MVP）

**HTTP POST + JSON = "任意识 HTTP 的东西"的最小公分母**——玩家外脑可以是 curl 脚本、云函数、nginx 反代、大模型 API 代理、树莓派，零 SDK 零握手；JSON 装任意字节（payload base64）。WS/gRPC/自定义二进制要求玩家服务器实现连接保持/重连/协议栈，MVP 不值得。
- MVP 边界：只做 POST 出站+回信入站。长连接（WS 出站）/gzip/二进制协议/批量打包=信号驱动（真实外脑性能需求出现再议）。
- **MVP 客户端实现边界（D-001b 落地口径）**：世界侧手搓 HTTP/1.1 短连接客户端（`Connection: close`，读写各设超时，无 reqwest/ureq——禁新增依赖）；端点仅支持本机回环 http（host 必须 127.0.0.1/localhost，bridges.json 里非本机 http 与 https 端点加载时 warn 拒收/停用）。payload 信封暂用 JSON 字节数组（base64 升级挂起，见 §2.8）。
- 对比锚：浏览器前端↔世界的 WS（net-protocol）是世界与浏览器之间的协议，与本桥（世界与玩家外脑）是两层协议，不共用管道，共用"客户端只发意图、服务器权威"的形状。

### 2.5 护栏（容量/速率/尺寸——工程保险丝，config 可调）

| 护栏 | 默认值 | 理由 |
|---|---|---|
| payload 上限 | 8 KB/信 | 侦查画图/弹道表够用，防大文件搬运滥用 |
| 每沙箱每拍 bridge_send | 1 次 | 与"每实体每拍 1 发"同款节律 |
| 每沙箱在途上限 | 常驻造物 4 条 / 活弹 1 条 | 防灌爆出站队列；活弹短命（寿命自管）1 条往返够用 |
| 出站超时 | 5 秒 | 对齐 architecture.md compute_timeout_ms 5000（旧稿唯一保留数值——超时后不投递，代码自管） |
| 回信读保险丝 | 1 MB（REPLY_READ_CAP，const 非 config） | worker 侧单响应读上限（头+体）——防坏服务器灌爆世界内存，工程保险丝不开放 config |
| 并发出站线程 | 8 | 世界侧网络池（64 实体×1发/拍 ÷ 8 线程，1 秒预算内宽裕） |
| 每账号并发会话上限 | 不设 | D-005 题⑤拍板"并发上限=不设（运营问题）" |

途满再发 → 返回码 3（世界不排队不重试，代码自己等）。护栏哲学：全是**容量护栏非玩法数值**（防灌爆/防 DoS/防卡世界），与 fuel 同性质（#029：工程保险丝无玩法意义）。全部入 config + menu 1.7 世界常数总账（标定锚：与接触容差/极速同账本）。

### 2.6 沙箱侧接口（api.md 增量——世界提供的全部，两个函数撑起整座桥）

```wat
(import "env" "bridge_send" (func $bridge_send (param i32 i32 i32) (result i32)))
;; bridge_send(port, ptr, len) -> 0 排队成功 / 1 无此端点 / 2 超限 / 3 在途满 / 4 桥未启用或已吊销
;; 只表示"进了邮筒"——不表示送达/已回复（异步跨拍，回信走 bridge_on_reply）

(func (export "bridge_on_reply") (param i32 i32 i32) …)
;; 可缺省导出。世界把回信字节写进沙箱内存（世界分配写入，与 attack payload 同款），collect 阶段调用
;; 缺省=收不到回信（信塞进无人收件箱，静默丢弃+日志，无副作用）
```
- **不做**（防越界，接口面最小化）：不做 bridge_poll（回信即投递无需轮询——poll 诱导每拍空转）；不做 bridge_status（诊断=发一封"你活着吗"的信，外脑自己答——世界不管外脑死活）；不做订阅推送（注入无门，见 2.7）。

### 2.7 注入无门的边界（外部→沙箱方向）

- 外部服务器**不能主动推消息进世界**：唯一入口=沙箱自己 bridge_send 发起的问答（回信是"回信"，不是"推消息"）。想搞"外脑主动情报推送"→ 玩家代码轮询自己的外脑（每拍一问"有新消息吗"）——轮询烧自己的 fuel，公平。
- 世界内沙箱↔沙箱消息不走本桥（那是 D-011 世界内数据通道的事）；本刀桥=对世界外出线。两个管道、同一法条（只送信不拆信）。

### 2.8 挂起项（本刀不做，信号驱动）

| 挂起项 | 等什么信号 |
|---|---|
| 中继转发（外脑转发消息给另一个外脑） | 玩家外脑真实出现"多跳转发/中继"玩法（A 的弹丸经 B 的服务器中转打 C） |
| 出站长连接（WS 出站） | 单信延迟成为实测瓶颈（5~10 拍/秒时代重估） |
| SL 式时间窗限流+信件截断 | 多人时代防灌爆（deleg_41cd4672 调研：Second Life llHTTPRequest 三重节流 25 封/20 秒+2048B 截断，二十年生产验证；现有在途上限 4 封是并发档，缺时间窗档与截断档） |
| payload 压缩 | 实测带宽成为瓶颈 |
| 语义层扩展（世界替玩家解析消息格式） | 永不（#011——世界不拆信） |
| 桥消息持久化（世界侧队列落盘） | 多真人时代（单机重启丢在途消息=可接受损耗） |
| 桥流量入回放流 | 多真人/回放仲裁立项时（回信投递拍由网络墙钟决定，同输入两次运行可差一拍——须先录桥流量才能仲裁/回放） |
| https 真客户端 | 玩家外脑真实上云时（MVP 手搓 http/1.1 仅本机回环；上云需要 TLS 栈=引依赖，届时统一选型） |
| base64 信封 | 现 JSON 字节数组（payload ≤8KB 时膨胀约 4 倍可接受）；外脑流量实测吃紧或跨语言解析阵痛真实出现再换 |
| 出站多线程 | 设计值 8 线程，D-001b 单线程先行；实测积压信号（出站队列滞留/回信跨拍延迟劣化）出现再扩 |

## 三、凭证保险库（#043 三铁律的工程落地）

### 3.1 保险库是什么

**账号层的"外部端点登记表"**：每账号最多 8 条，每条={port 别名, URL, 可选鉴权头集, 备注}。世界进程持有（内存+SQLite 加密存档，与快照同存储），**沙箱永远拿不到登记内容**——沙箱代码只写 port 编号。
- 登记入口：世界配置目录 `bridges.json`（账号级配置文件，与 me.txt 同族——MVP 无账号系统，单账号=世界所有者）。多真人时代切换为账号表（结构同、多行），接口不变。
- 结构示例：`[{ "port": 1, "url": "https://…", "headers": {"Authorization": "Bearer …"}, "note": "我的云函数" }, …]`——登记即生效（启动加载+热重载），变更记 INFO 日志。
- **世界代签（铁律①的实现形态）**：HTTP 由世界进程以自己的身份发出（不是以沙箱代码的身份），登记时配置的鉴权头原样贴上——**凭证落在世界进程的出站请求里，不落进沙箱内存**。世界=邮差，贴你登记时给的邮票，不印邮票。
- URL scheme 仅 https（MVP 本机调试 http://127.0.0.1 可 config 放开）。

### 3.2 port 别名机制（为什么用别名不用 URL 直传）

1. **铁律①**：沙箱内存不能有 URL（夺舍代码读内存=拿到你的服务器地址+凭证）——port 是唯一能在沙箱里出现的标识，本身零信息量（夺舍者只知道"有个 1 号端点"，不知道 1 号是谁/在哪/token 是什么）。
2. 代码可移植：同一段 WAT 换账号跑，port=1 指向不同 URL——代码不用改。
3. 保险库是账号资产（铁律③随账号永生），port 是代码与保险库之间的稳定接口。

### 3.3 保险库三问（土豆必问的验收口径）

1. **沙箱被夺舍了，我的外脑会怎样？**——铁律②启动：账号↔角色绑定一变（击杀/夺舍），世界**原子吊销该角色全部造物的外部连接使用权**——未发排队消息直接取消；在途已发出的 HTTP 收不回来（诚实的网络），回信到达时发现已吊销→丢弃+日志。凭证本体留在保险库（银行卡与副卡：冻结副卡不换卡号）。零窗口零第三方依赖（世界自己的事件循环执行吊销，不等外部服务配合）。
2. **新角色能继续用吗？**——铁律③：账号下重进的角色照常供证，外部资产随账号永生只跟角色断（重进零重配成本）。
3. **我的外脑能主动进世界吗？**——不能（注入无门，2.7）。首接知情提示：第一次接外部服务时世界明示凭证三铁律（#043 附则）。

结论：活弹的"活"已全部就位，本刀只补"外呼"。**桥面前造物平等**（弹/塔/城同权——桥不区分造物种类，#045 投射物组装学：弹丸=正常造物）；待遇面前不平等（4.2 参数分档）。

### 4.2 活弹专属待遇参数（dev-plan D-001 点名的缺口）

| 参数 | 活弹（投射物造物） | 常驻造物（塔/城） | 出处/理由 |
|---|---|---|---|
| fuel 配额 | **继承制**：出生时从创造者配额扣减继承，出厂下限 1000 指令（防 0 资源白嫖骚扰） | 全额（百万级保险丝甜点区） | D-005 题③继承制；#046 出厂下限 |
| 配额上限 | `CODEWORLD_PROJECTILE_FUEL_CAP` 默认 50_000 指令 | 百万级 | #046 衍生：上限防无限赖皮 |
| 在途消息上限 | 1 条 | 4 条 | 活弹短命，1 条往返（问-答）已覆盖制导需求 |
| bridge_send 频率 | 1 次/拍（同） | 1 次/拍 | 同节律 |

**短命造物的桥经济学**：活弹寿命自管（代码自杀/燃料尽即死，#045），按典型 30 拍算：一生最多 30 问。外脑制导（每拍问"往哪拐"）= 30 问预算；纯物理飞 = 0 问。**制导是花钱买精度**，物理弹道学是免费基线。与 #029"飞行不收税"不冲突：制导收的不是飞行税，是外脑咨询费——fuel 烧在沙箱自己的指令上（bridge_send 调用本身几步+on_tick 逻辑），与"谁的代码在跑烧谁的步数"（#046）同账本。外脑那边跑多少 FLOPS 世界不管也管不着——世界只管世界内的账。

### 4.3 集成点清单（CC 施工项）

- arena 侧：PendingSpawn **无改动**——沙箱=造物出厂自带，桥不是出生声明参数，是基础设施（凡有沙箱皆有桥能力）。
- main 侧：collect 阶段调 bridge_on_reply（与 on_attack 排队同款管线）；出站管理器独立线程（与 WS 快照线程同构 #026 辙）。

## 五、安全边界（外桥覆盖一切沙箱含弹丸 #038）

- **覆盖面**：一切有沙箱的实体（角色本体/造物塔/造物弹丸/游魂）——凡有沙箱皆可外呼；凡无沙箱（布景/痕迹/残影）无 bridge 能力。**沙箱=桥的使用资格**（沙箱=身份载体的通道版推论）。
- **弹丸沙箱外呼=活弹完全体**：弹丸每拍把视野（scan 结果）发外脑，外脑回"左转"，弹丸 thrust 转向——侦察弹→外脑分析→定制弹（OODA 循环，D-011 杀手级应用）。
- **世界进程出站面**：桥是玩家代码触达真实网络的**唯一出口**（沙箱无网络权，一切网络流量经世界进程代签发出）——单出口=可审计（INFO 日志每信一条：实体/port/seq/字节数，内容永不入日志）。沙箱内无 socket 原语（现行 wasmtime 环境已保证——import 表只有世界提供的函数，无网络类 import）。
- **DoS 边界**：出站速率=每沙箱每拍 1 发 × 实体上限 64 = 每秒最多 64 封（世界侧 8 线程消化，容量宽裕）；外部服务器被玩家自己灌爆=玩家自己的服务器自己管（世界只保证自己不被拖死：护栏+超时+线程池上限）。
- **信息外泄面**：信封含 entity/port/seq——外部服务器知道"哪个实体在问"（EntityId 可经登场日志对回生物名，与 battle 日志同级信息）。世界侧不泄露对手情报（快照/scan 数据不进信封——payload 是玩家代码自己写的，玩家泄露什么是玩家的事）。
