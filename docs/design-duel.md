# 决斗制攻杀设计稿（design-duel）

> **卷首语**：游戏的核心是规则而不是代码（土豆定则，2026-10-17）。Core War 借的是规则（40 年验证），不是代码。
> **状态**：设计稿 v0.1（2026-10-18），待土豆过目拍板。拍板前不派活。

## 一、问题（现状的缺陷）

现行实现是"接触即替换"：命中瞬间世界直接销毁目标旧代码、装入攻击者 payload（`replace_code` 一次调用，原子完成）。目标代码没有任何抵抗过程——**世界替攻击方宣布了胜利**。这不是攻杀，是邮政。

土豆定则（2026-10-17，三轮推演后拍板方向）：命中只是投递；之后攻击代码要在对方沙箱内**突破防御**才能完成后续动作——像爬虫 vs 反爬。完成覆写=击杀；复制走代码=偷窃；烧掉 fuel=消耗。

挂起判断被证伪的记录：design-binding.md 曾把"沙箱内双方代码共存攻杀"挂起，理由是"归玩家涌现，世界零预设"。此判断错误——在"接触即整体替换"原语下，玩家根本涌现不出决斗（B 的代码在决斗开始前就被销毁了）。**决斗需要世界给场地**。这是第三次从不同视角撞上同一堵墙（攻方算力推演/守方纵深推演/土豆的爬虫类比），三撞=正门。

## 二、调研定论（2026-10-18，勿再重复调研）

### Core War 机制（40 年验证，规则照抄的来源）

- **战场**：环形指令数组（标准 8000 格），每格一条指令（opcode+两字段）。**纯相对寻址**（程序不知道自己绝对位置，被搬移后仍能运行）。
- **关键指令**：DAT（数据/非法指令——**执行到即死，杀伤的本质**）；MOV（整条指令复制到目标格——唯一的覆写武器）；SPL（分裂新进程——算力兵力化）；CMP/JMZ（比较/条件跳——扫描嗅探）；ADD/SUB（指针步进）。
- **胜负**：进程队列清空判负（执行到 DAT/除零的进程死亡出队）；到 cycle 上限（标准 80000）双方仍在=平局。
- **标准参数**（ICWS'94）：coresize 8000 / max processes 8000 / cycles 80000 / max length 100 / min distance 100。
- **流派三角**：轰炸（克）扫描（克）复制（克）轰炸，无最优解，40 年元环境演化不衰。
- **战术全谱**（全部通过对内存的实际读写实现）：轰炸流（步进投 DAT）、扫描器（先晕后杀：SPL 弹拖慢→DAT 清场）、复制体（多副本抗单点）、吸血鬼（JMP 弹劫持进陷阱坑做苦力——劫持而非杀死）、imp 螺旋（MOV 0,1 永动爬行）、诱饵/隐身（假目标骗扫描器/B 字段归零伪装空内存）、自修复（备份+回填）、imp gate（门口工事持续 DJN 自减反爬虫）。

### 后裔与同类扫描

- **EXAPUNKS**：同网络程序互杀，但 KILL 一次罚 1 分——**击杀有代价才出博弈**，骚扰/占位/抢文件常优于硬杀。
- **Grey Hack**：持续世界的玩家互黑（进程/文件级），无内存决斗。
- **Screeps**：claim 攻防=打价值锚点+冷却式免疫盾，无代码级注入。
- **DARPA CGC**（机器攻防擂台）：**伤害必须可验证**——exploit 要附带可重放的攻击证明（PoV）才算分。
- **反爬四原语**（游戏化素材）：指纹（WAF 给 payload 做行为画像）；限流（cycle 配额）；蜜罐迷宫（AI Labyrinth：假内存区诱导攻击代码空转烧预算）；算力门票（Anubis PoW：访问敏感区前先解工作量证明）。
- **CTF pwn 抽象**：栈溢出=覆写跳转入口；ROP=不注入完整代码、重用沙箱内已有函数拼攻击；信息泄露先于攻击（先扫描后打击）；canary/ASLR=分层防御提高利用成本但不绝对——**任何防御都可破但值得破**。

### 关键空白（=我们的组合创新点）

**没有任何现存游戏实现"弹丸命中投递 payload → payload 在目标沙箱内与防御代码决斗"的完整链路。** Core War 有决斗无投递层；Screeps 有投递层无决斗。链路组合是原创，**平衡数据没有现成可抄，需自行标定**（此风险记入开放问题）。

## 三、机制层设计（世界要造的）

### 3.1 命中=投递（不是胜利）

弹丸命中 → 世界不再直接 replace_code。改为：在**目标沙箱内**开辟一块**决斗区**，攻击 payload 进入决斗区，与目标防御代码对峙。身体不动（还是那个实体），里面开战。

### 3.2 决斗场=共享内存区（MARS 的 WASM 版）

决斗区是一块双方代码都映射进来的**环形内存格阵列**（Core War 的 core 直接对应）。覆写只能发生在这块区内；世界只裁决区内指令流（当裁判，不当刽子手）。

### 3.3 交替执行与 fuel 赌注

- 双方**交替获得执行周期**（MARS 每 cycle 各执行一条的同构）。
- **兵力=fuel**：攻击方随弹丸携带 fuel 赌注（shoot 参数已预留）；防守方的赌注=沙箱当拍剩余 fuel。fuel 耗尽=进程清空=判负。
- 与宪法接驳：沙箱 fuel 是防死循环保险丝（工程参数禁入玩法）——决斗 fuel 是**新概念**（赌注池），两者分离记账，不违宪法。定价待拍板（见开放问题 4）。

### 3.4 杀伤判据=执行完整性（不是 HP）

一方判死的条件：**它的进程执行到非法指令，或进程队列清空**——不是"被写了多少"。防 spam 覆写无意义化：光写不算，必须**打断对方的执行流**。这是 40 年验证的最诚实判定。

### 3.5 结局谱（从"世界裁定"改为"攻方战果"）

| 结局 | 触发 | 对应玩法 |
|---|---|---|
| **覆写** | 攻方打赢：破坏守方执行流，将自己的代码装入主体 | 击杀（=现在的换血，但必须打赢才配） |
| **偷窃** | 攻方读走决斗区/主体数据区内容并带出（弹丸存活返回或广播） | 复制走代码=偷灵魂 |
| **消耗** | 攻方只投 SPL 型眩晕弹/耗 fuel 弹，不求占领 | 磨算力，为下一刀铺路 |
| **劫持**（参考吸血鬼） | 守方执行流被劫进攻方预设陷阱区，替攻方干活 | 夺权，fuel 反哺攻击者 |
| **驱逐** | 攻方 fuel 耗尽/超时，payload 出局 | 防御成功 |

（劫持是否进 MVP 见开放问题 5。）

### 3.6 超时语义：超时=防御方守住

决斗拍数封顶（防永动僵局——imp 打不死也打不赢的合法保底流派由此成立）。到时攻方 payload 强制出局，守方保留战损（被打坏的部分就是打坏了，世界不做回滚——诚实原则）。**拖平是有价值但次优的策略**（Core War 平局 1 分/胜 3 分的语义）。

### 3.7 裸奔特例（现状兼容，平滑升级）

守方没写防御代码（决斗区无防御布局）→ 决斗零时长，攻方瞬间完成覆写。**现行"接触即替换"成为本模型的退化特例**——已有玩家行为完全兼容，升级无破坏。

### 3.8 防御与攻击的原语（世界提供接口，怎么用归玩家）

守方可造（全部是玩家代码，世界零预设形态）：诱饵（假目标骗扫描）、隐身（统计特征伪装成空内存）、自修复（备份+回填）、门口工事（持续运行的拦截结构）、蜜罐迷宫（假内存区诱导攻方空转烧 fuel——AI Labyrinth 游戏化）、算力门票（敏感区前置 PoW 题）。
攻方可用：扫描（先读后打）、覆写、眩晕（SPL 型：迫对方进程暴涨、单进程变慢）、劫持、ROP 型（不注入完整代码、重用守方沙箱内已有函数拼攻击——CTF 游戏化，进阶玩法）。

### 3.9 击杀的成本与可验证性（EXAPUNKS/CGC 借鉴）

- 突破手段本身消耗 payload 自身 fuel/时间预算（击杀不是免费的，骚扰/消耗/偷窃与击杀形成成本博弈）。
- 战果由可重放的执行证据支撑（决斗区日志=战报，防争议仲裁）。

## 四、玩法层（玩家涌现，零预设，参考预期）

- 攻方流派预期即 Core War 三角：轰炸流（不求智取、地毯投弹）、扫描流（先探后打）、复制流（payload 多副本抗反制）——世界不设兵种，参数空间自然长出流派。
- 守方深度预期：防御代码本身成为城墙（土豆愿景兑现）——反爬写得越好越难被拿下；防御强度与性能成本直接互换（复制体=多进程=每个更慢，40 年验证的定价模型）。
- 连击/多刀语义自然消解：每刀独立决斗互不干扰；打包合成仍优于乱枪（发射前协同）。
- 元博弈预期：同一对手反复来犯 → 守方按上次攻击特征切换防御（P-space 思想），攻方需备多套 payload。

## 五、开放问题（待土豆拍板）

1. **决斗区规模**：Core War 标准 8000 格/80000 周期对我们太贵（世界还要跑物理）。初值倾向缩水一个量级（如 512 格/512 周期），用什么标定？（建议：先按"一场决斗≤1 秒墙钟"倒推。）
2. **守方可见性**：决斗中守方能看到攻方 payload 多少？三档：全盲（只有通用防御 API，门槛低）/ 可读决斗区（可针对性反制，谍战级）/ 分段（读到的越多花 fuel 越多）。
3. **偷窃偷到什么**：源码字节（对方全部智慧，太狠）vs 运行状态/记忆（情报级）vs 决斗区内容（最保守）。
4. **fuel 赌注定价**：弹丸携多少 fuel 进场？守方当拍剩余 fuel 全押还是限额？（牵动平衡：赌注太小=攻方骚扰免费，太大=击杀过易。）
5. **劫持进不进 MVP**：结局谱四选三还是全上？（劫持最花哨也最贵。）
6. **决斗期间的身体**：决斗进行时身体还在世界里——重力照拉、第三方照打？倾向：**照常**（世界不暂停，决斗是沙箱内的事，身体的物理生活照旧——被第三方打死则决斗随之作废，尸体归第三方）。
7. **性能预算**：决斗会不会拖慢世界 tick？（多场决斗并行时，裁决成本=每场每拍固定指令数，需设并发上限或排队。）

## 六、被否决方案（防重蹈）

- **接触即替换**（现状）：世界替攻方宣布胜利，无攻防过程——被土豆证伪（"不然怎么能叫攻杀"）。保留为裸奔特例。
- **换 MARS 当世界内核**：语言降级（Redcode vs WASM），物理/沙箱/fuel 全部重来。一票否决。
- **嵌 pMARS/corewa-rs 当决斗引擎**：双语言生态分裂+旧 C 包袱。否决——corewa-rs（MIT）只当规则参考实现对照。
- **真·沙箱内共存互攻（无场地裁判）**：需要世界发明"沙箱内执行权调度"整套法律且无判定权威。否决——决斗场（共享内存区+世界裁判）是共存思想的受控实现。

## 七、实施提示（拍板后展开任务书用）

- 不动：物理/弹道/绑定契约/发射痕迹/两阶段结算外层。
- 动：deliver_attacks 的投递语义（命中→开辟决斗区）；新组件决斗场（环形内存+交替执行+判负裁决）；replace_code 降级为"决斗胜利后的执行动作"；on_attack 门保留为"门铃"（快速通道秒拒弱攻击）。
- 排期建议：宪法级大刀，双审循环+旗舰模型；先出最小决斗原型（裸奔特例回归测试锚定现状不破）再扩结局谱。
