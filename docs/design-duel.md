# 决斗制攻杀设计稿（design-duel）v0.2

> **卷首语**：游戏的核心是规则而不是代码（土豆定则，2026-10-17）。Core War 借的是规则（40 年验证），不是代码。**世界只当硬件，不当刽子手。**
> **状态**：v0.2（2026-10-18），骨架经土豆多轮拷问定稿（角斗场→全内存战场→内存映射直连的演化见第七节否决档案）。剩 5 开放问题待拍板，拍板后展开任务书。

## 一、问题（现状缺陷）

现行实现"接触即替换"：命中瞬间世界直接销毁目标旧代码、装入攻击者 payload（`replace_code` 原子完成）——目标无抵抗过程，**世界替攻击方宣布了胜利**。这不是攻杀，是邮政。

土豆定则（2026-10-17）："命中只是投递，突破防御才算攻杀"（爬虫 vs 反爬类比）。design-binding 曾把"沙箱内双方代码共存攻杀"挂起为"归玩家涌现"——此判断被证伪：接触即替换的原语下玩家根本涌现不出决斗（守方代码在决斗开始前就被销毁了）。**决斗需要世界给场地。三撞（攻方算力推演/守方纵深推演/土豆爬虫类比）=正门。**

## 二、宪法原则（2026-10-18 本轮推演确立，全部土豆拍板）

1. **世界只当硬件，不当刽子手**：世界可传数据（像执行每条指令那样），但不得替任何一方决定或执行胜负。现行"换血"（世界帮攻方换模块）从战斗中退役——最大的裁判动作判了死刑。
2. **守方全内存皆战场**：无角斗场。命中时世界把守方沙箱整块内存**直接映射**给攻方（wasmtime 内存映射，像插一根数据线），此后攻方用自己的读写指令直接操作守方内存的每个字节——读就是读，写就是写，**中间无世界代码**。世界全程只剩：命中时插线、每拍看结果。
3. **引擎不可改，改魂等效**：WASM 运行时代码只读（技术铁律，安全根基）。引擎=思维方式（自我，连接器）；魂=数据/记忆（思考的原料）。攻方不能改守方"怎么想"，但能完全控制它"以为的现实"——**操纵比杀死值钱**（寄生虫改激素不改基因；VR 眼镜骗人：人没变，人看到的世界变了）。
4. **死亡靠断不靠改**：四条死路全部无人裁判——①life() 自返 false（自我了断）②引擎读到坏数据当场崩溃（WASM 运行时机械判定，=Core War"踩雷即死"的等价物）③燃料（步数配额）耗尽 ④生存点数归零。**扣扳机的永远是自己 的机器**，攻方只是诱因。世界只是看见了崩溃。
5. **驾驶者免疫夺舍**：决策在玩家大脑（鼠标驾驶），改魂骗不了大脑；但可被污染信息源（scan 数据被污染=基于假地图做真决策）。亲自下场的战略价值。

## 三、完整攻击链语法（身体负责抵达，灵魂负责征服）

```
代码调用 shoot（意图）
  → 弹丸实体诞生（身体 + 乘客 payload）
  → 弹道飞行（重力/阻力/CCD——世界物理）
  → 半路可被拦截（反制窗口；被拦=游魂死在半路）
  → 命中（接触=门票检票；同拍击飞先于投递→按实况落空）
  → 游魂登陆敌方沙箱（攻防开始，持续 N 拍）
  → 每拍双方各烧各的燃料（步数=思考的体力）
  → 攻方：扫描找要害 / 读（偷）/ 改（操纵/破坏）/ 耗（磨步数）
  → 守方：照常运行自己的代码——校验数据、修复、诱饵、陷阱
  → 结局：夺舍/偷魂/耗魂成功，或攻方燃料尽/超时被驱逐（防御成功）
```

**三段链缺一不可**：近战=贴身零成本选项；弹丸=游魂的机票（没有它=瞬发全图点名，物理世界塌——"全员狙击枪"已判过死刑）；游魂=进门后的战斗员（没有它=命中即胜负，攻防深度塌）。

**接触是投递门槛不是持续通道**（邮件模型）：投进邮箱后实体飞到哪代码跟到哪；同拍击飞先于投递→按实况落空。击飞=位置武器：推出接触距离/推进火力网/打乱阵型；反制=质量（重=推不动）。

## 四、战果谱与状态谱

| 战果 | 机制 | 备注 |
|---|---|---|
| 夺舍 | 改魂改到守方为自己干活（傀儡） | 傀儡是资产（持续产出），死尸只有一次性战利品——**攻防最优解很少是弄死而是降服** |
| 偷魂 | 直接读走守方内存字节（决策表/情报/记忆） | 读到的就是拿到的，零转手 |
| 耗魂 | 磨干守方燃料（SPL 眩晕思想：逼对方步数烧在无用功上） | 为下一刀铺路 |
| 击杀 | 诱导四条死路之一 | 触发三合死亡+掠夺（#035） |
| 驱逐 | 攻方燃料尽/超时——防御成功 | 超时=防御守住，拖平合法但次优 |

**状态谱：健康 > 傀儡 > 死亡。** 傀儡不触发死亡结算（耻辱不记账，死亡才记账）；被解放（插件换回/魂修复）不触发任何结算。

裸奔特例：守方无防御布局→决斗零时长瞬间拿下——现行"接触即替换"成为本模型的退化特例，已有玩家行为完全兼容，升级无破坏。

## 五、燃料双重身份法（宪法新立）

- 燃料=步数计数器：每拍每沙箱一箱步数，每指令 -1，归零暂停，下拍重发。本质一句话：**这一拍最多允许跑多少步，不许无限运行**（防死循环保险丝）。
- **日常身份**：纯保险丝，禁入玩法（旧宪法不变，"悬停折寿"类伪约束仍否决）。
- **攻防会话身份**：步数=兵力。攻方赌注=弹丸出厂携带（shoot 声明，带多弹贵——攻击成本内置）；守方赌注=本体+插件当拍余额（防御深度=器官们能烧多少）。
- 类比：氧气平时免费呼吸，潜水时气瓶是命根。两身份必须显式立法隔离，防日常行为按燃料收费死灰复燃。

## 六、居民四形态分类法（世界 2.0 总纲，与插件化 D-006 衔接）

| 形态 | 沙箱 | 身体 | 例子 | 死法 |
|---|---|---|---|---|
| **本体** | 连接器（永不可改，BIOS）+插件们 | 有（一具） | 角色 | 连接器停=死（四条死路） |
| **造物** | 有 | 有（自己的） | 塔/弹丸/城 | 被打坏/契约消亡 |
| **游魂** | 有 | 无（搭弹丸/借宿） | 攻击 payload/夺舍者 | 燃料尽/被驱逐/夺舍转正 |
| **布景** | 无 | 有（虚的） | 山川/河流/墙 | 不可死，只可物理改 |

- 判据一句话：**有沙箱=居民，无沙箱=布景**。插件=沙箱造的无身器官（随本体死；造物是儿子独立生死，插件是器官共存亡）；游魂=离体无身（攻击形态本身）。
- **本体能力 vs 造物能力**：本体能力=行为指南（下线留存时的活法：是跑是跳是攻击）→插件实现；离体功能（攻击/塔/城）→必须造物（插件无身体飞不出去）。
- **游魂不能独立发射**（无身体=世界看不见它：无坐标无速度无位置）；唯一门票=搭弹丸命中。外接算力桥是唯一"免机票通道"——自己开的门随便通信，攻别人的门必须走物理（**通信自由，注入无门**）。
- **攻防目标清单封版**：连接器不可攻（压舱石）；插件可换装/改魂/拔除（攻防主战场）；魂可偷/污/改；身体走物理；造物走契约产权；游魂是攻击本身。

## 七、被否决方案（防重蹈，含演化路径）

- **接触即替换**（现状）：世界替攻方宣布胜利。退役；"换血"降级为夺舍确认后世界执行既成事实的收尾动作（唯一保留的世界动作，且只在打赢后）。
- **角斗场/决斗区**（v0.1 方案）：在守方内存划专门战区——真空罩子，场内输赢要经一次转手才落本体。被土豆否决（"攻防不应有世界参与"）→ 改全内存战场+内存映射直连。
- **隔墙对轰**（决斗接口方案）：世界当传话裁判，掠夺/夺舍变成世界代办。被土豆否决（爬虫是真拿到数据，不是收裁判转交的复印件）。
- **双方代码同居一块新内存**（贴身原版）：两套世界观并存。被"全内存战场"取代——留其神（攻防在内存层）去其形（不造第二块内存）。
- **换 MARS 当内核 / 嵌 pMARS**：语言降级/双生态分裂。corewa-rs（MIT）仅作规则参考。
- **全游魂化攻击**（无实体直接注入）：瞬发全图点名，物理世界作废。否决。
- **世界预置求生本能**（零代码玩家方案）：世界预设玩法违 #011。零代码玩家路线=模板生态+驾驶台阶（dev-plan D-006）。

## 八、调研定论（2026-10-18，勿再重复调研）

**Core War 机制**（规则照抄来源）：8000 格环形内存/18 指令/DAT 踩雷死（=咱们的崩溃死）/SPL 算力兵力化（=咱们的燃料战）/超时平局/流派三角（轰炸克扫描、扫描克复制、复制克轰炸）/诱饵/自修复/门口工事——全部战术思想在本设计内以"内存读写+燃料"自然涌现，不搬格子形式。
**后裔扫描**：EXAPUNKS（击杀有代价才出博弈）；CGC（伤害必须可验证——战果由可重放执行证据支撑，决斗日志=战报）；反爬四原语（指纹/限流/蜜罐迷宫/算力门票——守方可用原语）；CTF（信息泄露先于攻击=先扫描后打击；ROP=重用守方已有函数拼攻击，进阶）。
**关键空白**：投递+决斗完整链路无先例（Core War 有决斗无投递，Screeps 有投递无决斗）——组合创新，平衡数据自行标定。

## 九、开放问题（剩 5 题，待拍板）

1. **守方可见性**：决斗中守方能看到攻方 payload 多少？全盲（通用防御 API，门槛低）/可读（谍战级）/分段（读越多烧越多）。
2. **偷魂带走什么**：全部内存（源码级狠）/决斗相关数据段/读多少算多少（按燃料定价——倾向）。
3. **燃料赌注数值**：弹丸出厂携带上限/守方可否限额应战（防骚扰免费化）。
4. **夺舍确权动作**：改完魂是否需"守住 N 拍"才转正（防反复横跳）——倾向要。
5. **性能预算**：多场决斗并发的 tick 上限（裁决成本=每场每拍固定步数，需并发上限或排队）。

## 九B、多游魂条款（2026-10-18 土豆拍板，宪法级）

**世界允许多段代码同时进入守方沙箱攻击——至于它们进去之后怎么相处，是玩家代码的事，世界不管。**

- 结构（现实同构：服务器+多连接/DDoS）：命中的弹丸各开各的会话，**多游魂并存**，共享守方燃料池，各场独立结算。守方代码照常跑+同时应对所有来犯者——燃料=守方总带宽，群殴的意义=耗尽注意力（DDoS 结构天然成立：多发轻弹围耗/单发重弹破门）。
- **互斥/排队/互攻/配合/围殴——零立法**：互斥是守方可选的防御策略（用燃料分配表达侧重），互攻是攻方作者的代码天才（内存读写权已是完整表达力），世界不替玩家设计战斗规则。
- 一句话：**世界开的是网吧不是擂台**——一人一机各玩各的，想跟隔壁打起来是你们的事。
- 被否决的中间方案（防重蹈）：会话互斥（MVP 简化方案——被土豆"现实中多段代码可同时攻击一段代码"否决）；游魂互攻需专门规则（否决——表达力已够，规则多余）。
- 关联：连环刀场景自动消解（v0.2 守方代码永不被替换，多刀=多会话并存，发射前打包仍是更优协同但非必需）。
