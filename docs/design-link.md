# D-011 世界内链路段设计定案：控制链 + 数据通道 + 存储块

> 状态：设计定案，待施工 ｜ 定案日期：2026-10-23 ｜ 参与者：土豆（产品/规则，2026-10-18 三件套定案+#038 通道公理）、Hermes（实施设计）
> 输入：decisions.md #038（通道公理与三层分离）+ dev-plan D-011 条目 + design-duel.md 十一节 + design-bridge.md 六节（分工表）
> 定位：宪法 #038 的世界内段实施刀。外桥（D-001）已修通"对世界外"出线，本刀修世界内：链（纵向家庭通道）+消息（横向陌生通道）+存储（公开信箱）。

## 一、三件套与三层分类学的对号

宪法 #038 三层分类学：搬运消息→信息通道；直接访问→沙箱通道；位置碰撞→物理。D-011 三件套全部落在**信息通道**层——世界只送信不拆信，全部零内容解释（#011）。

| 件 | 通道方向 | 接口 | 投递回调 |
|---|---|---|---|
| 控制链 command | 母体 → 全部活链造物（下行广播） | `command(ptr, len) -> i32` | 造物导出 `on_command(offset, len)` |
| 链路回传 report | 活链造物 → 母体（上行） | `report(ptr, len) -> i32` | 母体导出 `on_report(from, offset, len)` |
| 数据通道 send | 任意沙箱 → 视口内坐标实体（横向） | `send(x, y, ptr, len) -> i32` | 对方导出 `on_message(from, offset, len)` |
| 存储块 storage | 造物公开信箱（写自己/贴身读对方） | `storage_write(ptr, len) -> i32` / `storage_read(x, y, ptr, cap) -> i32` | 无回调（拉读非推送） |

- **与外桥的分工（design-bridge 六节既定）**：外桥=对世界外出线（HTTP/外脑）；本刀=世界内管道。两个管道、同一法条（只送信不拆信）。
- **与沙箱通道（决斗/接触互授）的区分**：本刀全部接口不触碰对方沙箱内存——send 送的信对方自愿收（开门=导出回调），storage 读的是世界侧公开块非沙箱内存。直接访问仍然只有物理接触→决斗会话一条路。

## 二、链三态与账本（#038 立法实施口径）

链三态（dev-plan D-011 既定）：**无链（放生，默认）/活链（可控+可传）/断链（孤儿按 binding 契约活）**。

### 2.1 link=出生声明（binding 家族新成员）

- `spawn` 第 20 参 `link: i32`：`0`=无链（默认，现状语义零回归）/`1`=活链。非法值钳 0 并 warn（同 clamp_binding 先例）。
- **链账本落在实体字段**：`Entity.link_to: Option<EntityId>`（serde default None，旧快照零迁移）——与 `bound_to` 同款形态、同款快照待遇。
- **链与契约正交**：binding 管生死（fade_on_death 等），link 管通信。可自由组合：link=1+binding=0（母体死后造物活着但链断了——孤儿按 unbound 活）、link=1+binding=1（母体死当拍同生+链断无感）。

### 2.2 断链

- 唯一断链事件：母体实体死（is_alive=false）。当拍起该母体名下全部链标记断（link_to 清 None+INFO 日志一条汇总）。
- 断链不可逆（MVP 无复活）。断链不触发造物死亡——生死归 binding 契约，控制=活电话，电话挂了人还活着（契约=遗嘱 vs 控制=活电话的宪法区分，#035/#038）。
- 断链后：command 找不到活链返回 0；report 返回断链码。

### 2.3 寻址定案：广播制，弃编号制（本刀最重要的实施决定）

**command = 向自己的全部活链造物广播**，不做"第 N 个孩子"编号寻址。理由：

1. **失忆问题**：沙箱不持久化（重启内存清零），母体记不住孩子编号；世界侧编号持续递增，重启后重数会撞号=发错人（安全事故）。
2. **宪法契合**：谁响应哪条指令=玩家代码的事——指令内容里带"给谁"的标记，孩子自己过滤。世界零预设（#011）。
3. **叙事正统**：飞剑剑诀本来就是万人一面（一诀控万剑）；风筝流单弹=广播退化为单发，无损。
4. spawn 返回值语义不变（1=排队成功），零兼容破坏。

**report 上行自动沿链**：造物调 report 无需寻址（链连着呢），世界查 link_to 找母体。`on_report(from: i64, offset, len)` 的 from=发送造物 EntityId 低 64 位（field 信箱既定先例，LE）——母体多孩子区分靠它；孩子自己的状态玩家写进消息内容。

### 2.4 夺剑反杀（宪法预言的涌现验证）

造物可被决斗攻陷（attack_at 点命中制，造物=格对齐 AABB）。游魂进驻飞剑沙箱后：**链还连着原母体**（link_to 是实体字段，代码改不了）——新主代码照收原母体的 on_command 剑诀广播+可用 report 伪装上行。原主不知道剑已易主继续广播=情报单向透明。"放风筝的人自己也在被钓"（#038 原文）零新立法天然成立。测试锚覆盖（攻陷后链仍在+report 照投）。

## 三、控制链 command / report（纵向通道）

### 3.1 `command(ptr: i32, len: i32) -> i32`（下行广播）

- 调用方=任意有沙箱实体（玩家本体/造物都能当母体——造物造造物即"子链"）。
- payload 从调用方 memory `[ptr, ptr+len)` 读取；len 超上限拒绝（0 返回）。
- 世界查本实体名下全部活链造物（link_to==本实体 且 存活），逐个入队投递；**返回正数=入队链数，0=无活链或参数坏**。
- 每拍 1 次（同 bridge_send 节律）；无视口限制（链=声明关系，风筝线可放出屏幕——风筝流成立前提）。

### 3.2 `report(ptr: i32, len: i32) -> i32`（上行）

- 调用方=活链造物（link_to 有值）；世界沿链投给母体。
- 返回 1=入队 / 0=参数坏 / 2=无链或断链（母体死）。
- 每拍 1 次；无视口限制。

### 3.3 投递（复用 bridge_on_reply 全套先例）

消息当拍入队，**阶段二 a-1 位**（外桥回信同相位）投递：grow 分配（offset=旧内存末尾，新增零页永不覆盖玩家数据）→ 写入 → 预算包裹调回调（probe_fuel 同档独立预算——接收方为收信付费的上限是防守预算，与 on_attack/on_probe 同族）→ 缺省导出=零副作用丢弃+INFO（信塞进无人收件箱；**记账照结算**——不泄漏语义）。
- 多消息同拍投递按（目标 EntityId，源 EntityId）升序定序（确定性铁律）。
- 目标已死→丢弃+INFO（死亡竞态，同外桥"回信无人认领"）。
- 投递回调签名错误（有导出但签名不符）→ 不写内存不调用零副作用（P2-A 先例：不留半副作用）。

## 四、数据通道 send（横向通道）

- `send(x: f64, y: f64, ptr: i32, len: i32) -> i32`：坐标寻址（与 probe/attack_at 同哲学——点寻址，所见即所发）。
- 门槛：目标实体必须在**发送方视口内**（visible 列表成员——"屏幕内无欺骗"的发送版：看不见的发不到，想发先 scan）。
- 返回 1=入队 / 0=参数坏 / -1=坐标无实体或不视口内。
- 每拍 1 次；对方聋（无 on_message 导出）=入队成功但投递作废+INFO（通信自由=发信自由；开门=收信自由。注入无门宪法落地）。
- `on_message(from: i64, offset, len)`：from=发送方 EntityId 低 64 位。
- **不做**（接口面最小化，防越界）：不做 send_ack/送达回执（消息发出≠送达，代码自理）；不做广播 send（广播=玩家自己循环坐标发）；不做视口外投递（那是链或外桥的事）。

## 五、存储块 storage（公开信箱/移动硬盘）

造物=移动硬盘的完整叙事：前线造物 storage_write 写情报 → 飞越战场（数据在世界侧，不烧沙箱燃料、不占沙箱内存）→ 后方母体贴身 storage_read 读走=信鸽中继。

- 容量固定 `CODEWORLD_STORAGE_CAP`（默认 4096B，config 可调）——**容量护栏非玩法数值**（同 field 信箱 516B/沙箱 64MB 先例；不是 spawn 参数——想要大存储用沙箱内存+on_probe 应答，那是玩家自己的事）。
- `storage_write(ptr, len) -> i32`：全量覆盖自己的公开块。返回 N=写入字节数 / -1=超容拒绝（不截断——硬盘写一半=坏盘，诚实拒绝）/ 0=参数坏。每拍 1 次。
- `storage_read(x, y, ptr, cap) -> i32`：**贴身读**（距离 < r_self + r_target + 0.5，与 melee 判距同款严格 <——读硬盘=物理凑过去读）。返回 N=读到字节数写入 memory[ptr..ptr+N) / 0=cap 不足或指针坏 / -1=坐标无实体 / -2=够不着 / -3=对方无存储（空块返回 0——-3 与 0 区分"没硬盘"和"空硬盘"）。
- 读自己：storage_read 自己坐标（get_pos）距离=0 判据天然成立，零新接口。
- **与"接触传导"挂起项的区分**：挂起的接触传导=飞剑回鞘（接触自动连通沙箱内存，沙箱通道层）。storage_read=主动 import 拉读世界侧公开块（信息通道层），不触碰对方沙箱内存。两者不冲突，后者不占用前者的挂起席位。
- **快照**：storage 块随实体入快照（serde default 空——重启不丢 vs 沙箱内存重启丢，存储块天然比内存耐用）。

## 六、燃料与限流总账（#046 口径）

- **发送侧**：command/report/send/storage_write/storage_read 调用本身烧调用方 tick 燃料（调用即指令，自然计量）。
- **接收侧**：on_command/on_report/on_message 投递烧接收方 probe_fuel 独立预算（与 on_attack/on_probe/on_contact/bridge_on_reply 同族——外部回调防守档预算，不占接收方主配额）。**围殴经济学同款**：谁逼谁收信谁占便宜的结构不存在——发信烧自己，收信有独立上限兜底。
- **限流**：五 import 各 1 次/拍/沙箱（同 bridge_send 节律；与 bridge_pending 分管道分记账）。
- **护栏**（全 config，容量护栏非玩法数值）：`CODEWORLD_LINK_PAYLOAD_MAX`（默认 8192B，同桥 payload_max 锚）、`CODEWORLD_STORAGE_CAP`（默认 4096B）。

## 七、否决/挂起清单（防重蹈）

- ❌ **编号寻址（command(N, …)）**——重启失忆撞号=发错人安全事故；广播+玩家内容过滤取代（2.3）。
- ❌ spawn 返回值改为家庭号——破坏 ==1 判返回值的老代码，且广播制后无必要。
- ❌ 链上写对方存储块（母体直接写孩子硬盘）——身体是造物自己的，要它写就发 command 指令（自治哲学）。
- ❌ send 视口外投递/中继转发——视口=门槛；跨视口走链（纵向）或外桥（出世界），横向中继=玩家自己拼信鸽（storage 块就是给这个的）。
- ❌ 送达回执/消息查询类接口（poll/status）——接口面最小化（同外桥否决 bridge_poll 先例）。
- ❌ 世界侧消息持久化（落盘）——同外桥挂起理由，多真人时代再议。
- ⏸ 挂起：链可否被物理切断（等力场立法，dev-plan 既定）；接触传导（飞剑回鞘，沙箱通道层另议）；消息加密/信封格式（玩家内容自理）。
